## A-2. 동기화 프로토콜 · 셀프호스트 sync server · 인증(hkey)
### Takeaway
2.1.57+ 내장 sync server는 환경변수 username/password + `/sync/hostKey` 교환으로 얻는 장기 토큰(hkey)이 전부이며 TLS는 프록시에 위임한다. 엔터프라이즈 인증 모델이 아니라 "단일 바이너리 self-host 운영 단순성"의 참고 사례다.
### Cited Findings
- 내장 서버 "desktop version of Anki as of version 2.1.57+", 독립 Rust 서버는 "2.1.66+". 실행: `SYNC_USER1=user:pass anki --syncserver`; pip `python -m anki.syncserver`(Python 3.9+); `cargo install --locked --git https://github.com/ankitects/anki.git --tag 25.02.5 anki-sync-server`(protoc 필요) — [Anki manual: Sync Server](https://docs.ankiweb.net/sync-server.html)
- 환경변수: `SYNC_USER1`(필수, `SYNC_USER2`…), `SYNC_BASE`(기본 `~/.syncserver`, "must not be the same location as your normal Anki data folder"), `SYNC_HOST`/`SYNC_PORT`, `PASSWORDS_HASHED`(`username:password_hash`, PHC 포맷), `MAX_SYNC_PAYLOAD_MEGS`(기본 100MB), `SYNC_ENDPOINT`(`/sync/`)/`SYNC_ENDPOINT_MEDIA`(`/msync/`)는 구형 클라이언트 전용 — 같은 문서
- "listens on an unencrypted HTTP connection"; 로컬망 제한·VPN(Tailscale)·HTTPS 리버스 프록시 권장; 서브패스 URL은 끝에 `/` 필수; Caddy `read_buffer 512k`; iOS는 TLS 1.2 필요; "newer clients may depend on changes to the sync protocol"; 서드파티 서버 비권장 — 같은 문서
- `login.rs`(AGPL): `SyncAuth { hkey: String, endpoint: Option<Url>, io_timeout_secs: Option<u32> }`, `HostKeyRequest { "u": username, "p": password }`, `HostKeyResponse { key }`, `sync_login(username, password, endpoint, client)` → `hkey = resp.key`; 테스트 경로 `"/sync/hostKey"` — [rslib/src/sync/login.rs](https://raw.githubusercontent.com/ankitects/anki/main/rslib/src/sync/login.rs)
- (2차) 24.11/25.x에서 애드온의 구식 `sync_login()` 호출이 거부되며 `auth = mw.col.sync_login(..., endpoint=mw.pm.sync_endpoint()); mw.pm.set_sync_key(auth.hkey)` 권장 — [Anki Forums](https://forums.ankiweb.net/t/is-there-any-supported-way-to-authenticate-ankiweb-login-without-using-the-gui/67637); 비공식 서버 [ankicommunity/anki-sync-server](https://github.com/ankicommunity/anki-sync-server/)
### Inferences
- OAuth/OIDC·역할·세션 만료가 없으므로 우리 auth 설계에는 반면교사. 반면 "환경변수 + 파일 저장소 + 프록시 전제" 배포 모델은 소규모 self-host에 차용 가능. Anki 프로토콜 호환 구현은 비용 대비 가치가 낮고 `.apkg` 내보내기로 충분.
### Gaps
- hostKey 이후 전체 요청 목록(meta/start/applyChanges/chunk/finish, 미디어)과 `PASSWORDS_HASHED`의 KDF는 미확인.

## A-3. 컬렉션 스키마(.apkg) · revlog · FSRS 상태 저장
### Takeaway
`notes`(내용) → `cards`(스케줄 단위) → `revlog`(append-only 로그) 3단 구조. 최신 Anki는 FSRS 상태를 `cards.data` JSON(`s,d,dr,decay,lrt`)에 넣고 `revlog.factor`에 FSRS 난이도를 정규화 기록한다. 우리 `review_item`/`review_log` 테이블의 최소 모델로 직접 참고 가능.
### Cited Findings
- schema11.sql: `col(id,crt,mod,scm,ver,dty,usn,ls,conf,models,decks,dconf,tags)`, `notes(id,guid,mid,mod,usn,tags,flds,sfld,csum,flags,data)`, `cards(id,nid,did,ord,mod,usn,type,queue,due,ivl,factor,reps,lapses,left,odue,odid,flags,data)`, `revlog(id,cid,usn,ease,ivl,lastIvl,factor,time,type)`, `graves(usn,oid,type)` — [schema11.sql](https://raw.githubusercontent.com/ankitects/anki/main/rslib/src/storage/schema11.sql)
- 컬럼 의미(스키마 v11 기준): `notes.id` 생성 epoch ms, `guid` 동기화용, `mid` 노트타입, `flds` 0x1f 구분, `sfld` 정렬 필드, `csum` 첫 필드 SHA-1 앞 8자리; `cards.type` "0=new, 1=learning, 2=review, 3=relearning", `queue` -1 suspended/음수 buried/4 preview, `due`는 new=순서·learning=epoch초·review=컬렉션 생성일 기준 일수, `factor` 천분율(2500=2.5x), `left`=a*1000+b, `odue/odid` 필터덱 원본; `revlog.ease` 복습 1 wrong/2 hard/3 ok/4 easy, `ivl` 음수=초/양수=일, `factor` "If FSRS is enabled, it is replaced by the FSRS difficulty normalized to a 100-1100 range.", `time` ms(60000 상한), `type` 0 learn/1 review/2 relearn/3 filtered/4 manual/5 rescheduled; v11은 노트타입(`models`)·`decks`·`dconf`·`conf`·`tags`를 `col`의 JSON으로 저장 — [AnkiDroid wiki: Database Structure](https://github.com/ankidroid/Anki-Android/wiki/Database-Structure)
- `CardData`(`cards.data` JSON): `"pos"` original_position, `"s"` fsrs_stability, `"d"` fsrs_difficulty, `"dr"` fsrs_desired_retention, `"decay"`, `"lrt"` last_review_time, `"cd"` custom_data("so v3 custom scheduling code can persist state"); 미설정 필드 생략; `memory_state()`는 s·d 모두 있을 때만 반환; 반올림 s 4자리/d 3/dr 2/decay 3; 예 `{"s":123.4568,"d":1.235,"dr":0.99,"decay":0.123}` — [rslib/src/storage/card/data.rs](https://raw.githubusercontent.com/ankitects/anki/main/rslib/src/storage/card/data.rs)
- (2차) `.apkg`는 ZIP; 최신 패키지는 "a real v18 SQLite (`collection.anki21b`, zstd-compressed) AND a decoy v11 SQLite at `collection.anki2`" — [PyPI ankisync2](https://pypi.org/project/ankisync2/); "collection.anki2 is a dummy for older clients" — [Anki Forums](https://forums.ankiweb.net/t/collection-anki2-in-exported-apkg-file/44380); 파서는 anki21b(zstd)→anki21→anki2 순 시도 — [vultan source](https://docs.rs/crate/vultan/1.0.1/source/src/anki.rs); 미디어는 번호 항목 + `media` 매핑 JSON — [anki-apkg-parser](https://github.com/74Genesis/anki-apkg-parser)
### Inferences
- 우리 최소 스키마: lesson(Git Markdown 원천) → review_item(user×lesson; s/d/dr/decay/last_review/due) → review_log(append-only: item_id, rating 1–4, elapsed, scheduled, reviewed_at, duration_ms). Anki가 revlog를 삭제하지 않고 옵티마이저 입력으로 쓰므로 review_log는 불변 테이블로.
- FSRS 상태를 JSON 컬럼에 둔 것은 알고리즘 버전 간 필드 변화(FSRS-6의 `decay`) 흡수용으로 보임 → 우리도 JSONB + 알고리즘 버전 키 저장 권장. `.apkg`는 내보내기 타깃으로만 취급.
### Gaps
- 최신 스키마(v18 추정)의 `decks/notetypes/fields/templates/deck_config/config/tags` 테이블 정의는 `schema15_upgrade.sql` 404로 미확인(디렉터리에는 schema11.sql만 보임). `.apkg` `meta` protobuf·`.colpkg` 구조 1차 소스 없음.

## A-4. FSRS 알고리즘·라이브러리: 라이선스/버전/API, 재사용 경계
### Takeaway
FSRS는 Anki와 독립된 open-spaced-repetition 라이브러리로 재사용 가능: fsrs-rs BSD-3-Clause(7.0.0, FSRS-6/7 자동), py-fsrs MIT(6.3.2, FSRS-6 21 파라미터), ts-fsrs MIT(6.0.0, FSRS-7 기본). Anki(AGPL)는 fsrs-rs의 소비자일 뿐이므로 플랫폼은 FSRS만 가져오면 된다.
### Cited Findings
- 알고리즘: R(회상 확률), S(R=90% 간격), D∈[1,10]; FSRS-6 망각곡선 R(t,S)=(1+factor·t/S)^(−w20), factor=0.9^(−1/w20)−1; 파라미터 FSRS-4.5 "17 parameters", FSRS-5 "19 parameters", FSRS-6 "21 parameters"; FSRS-6 신규 "The forgetting curve's decay is trainable."(w20), 같은 날 리뷰 공식 변경(w17–w19); 평점 1 again/2 hard/3 good/4 easy; FSRS-7 언급 없음 — [awesome-fsrs wiki: The Algorithm](https://github.com/open-spaced-repetition/awesome-fsrs/wiki/The-Algorithm) (fsrs4anki 위키 페이지는 여기로 이전됨 — [fsrs4anki wiki](https://github.com/open-spaced-repetition/fsrs4anki/wiki/The-Algorithm))
- fsrs-rs: "BSD-3-Clause license", "FSRS for Rust, including Optimizer and Scheduler", "both FSRS-6 and FSRS-7", "FSRS-6 and FSRS-7 are selected from the parameter count"; API `FSRS::default()`, `next_states(previous_state, desired_retention, elapsed_days)`, `memory_state_from_sm2(...)`, `memory_state(FSRSItem{reviews}, ...)`, `compute_parameters(ComputeParametersInput{train_set,..})`, `compute_parameters_from_card_prefixes`, `evaluate_from_card_prefixes`, `CostAdrPolicy`("a 15-parameter cost-conditioned desired-retention policy"); "springs from MaiMemo's DHP model" — [fsrs-rs](https://github.com/open-spaced-repetition/fsrs-rs); 레지스트리 7.0.0 "released Nov 10, 2026"(6.7.0도 같은 날), "Used in 8 crates (7 directly)" — [lib.rs: fsrs](https://lib.rs/crates/fsrs)
- py-fsrs: MIT, `pip install fsrs`, `from fsrs import Scheduler, Card, Rating, ReviewLog`, `card, review_log = scheduler.review_card(card, rating)`, `Optimizer(review_logs)`(`fsrs[optimizer]`), `get_card_retrievability`, `reschedule_card`, `compute_optimal_retention`, "a set of 21 model weights" — [py-fsrs](https://github.com/open-spaced-repetition/py-fsrs); PyPI 6.3.2 "Aug 9, 2026", "Python >=3.10" — [PyPI: fsrs](https://pypi.org/project/fsrs/)
- ts-fsrs: MIT, "`ts-fsrs` v6 and `@open-spaced-repetition/binding` require Node.js `>=24.0.0`", "It defaults to FSRS-7; the library version and the FSRS model version are independent.", 지원 FSRS 3/4.5/5/6/7; API `DefaultScheduler()`, `newCard({now})`, `preview({card, now})`, `review({card, grade: Rating.Good, now})` — [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs); npm 6.0.0, engines ">=24.0.0", exports `./models/fsrs-6`, `./models/fsrs-7` — [npm registry](https://registry.npmjs.org/ts-fsrs/latest)
- Anki 운영 파라미터: "FSRS can only be enabled globally"; Desired retention 기본 90%, "This is the most important setting in FSRS. Higher retention leads to shorter intervals and more reviews per day.", 97% 미만 권장; Optimize "uses machine learning to learn your memory patterns", "once every month is sufficient"; "Compute minimum recommended retention"은 "removed as of anki version 25.07"; Historical Retention 기본 90%; Maximum Interval 기본 100년; 학습 단계 1일 미만(10m/30m) — [Anki manual: Deck Options](https://docs.ankiweb.net/deck-options.html)
- (2차) Anki 25.07: "FSRS-6 brings further algorithm improvements by @L-M-Sherlock in #3929", fsrs-rs v3.0.0, "use log loss instead of RMSE(bins)" — [newreleases.io anki 25.07](https://newreleases.io/project/github/ankitects/anki/release/25.07)
- 구현체 목록(CC0): py-fsrs(v6+optimizer), fsrs-rs(v6+optimizer), fsrs-browser, ts-fsrs(v3–v7), go-fsrs(v5), rs-fsrs-java(v5), FSRS-Kotlin(v6), swift-fsrs(v5), dart-fsrs(v4.5), cljc-fsrs(v4), haskell-fsrs(v7) 등 — [awesome-fsrs](https://github.com/open-spaced-repetition/awesome-fsrs)
### Inferences
- 재사용 가능: 스케줄러/옵티마이저/시뮬레이터(순수 함수: 상태+평점+시각→다음 상태). Anki 결합: 프리셋 단위 파라미터 UI, 학습 단계·필터덱·custom scheduling JS, revlog→FSRSItem 변환, 동기화.
- 백엔드별 권장: Python=py-fsrs(FSRS-6), Rust=fsrs(6/7 자동), TS=ts-fsrs(FSRS-7, Node 24+). 모델 버전은 파라미터 배열 길이로 식별되므로 파라미터 배열을 그대로 DB 저장하면 이식 가능. fsrs-rs 7.0.0이 2026-11-10 등록 직후이므로 FSRS-6(21개)을 기준선으로 잡는 것이 안전.
### Gaps
- FSRS-7 수식·파라미터 수·변경점 미확인(위키 미반영). Anki 26.x의 FSRS-7 탑재 여부 미확인. Jarrett Ye 원저자 표기는 PR 작성자(@L-M-Sherlock)로만 간접 확인.

## C-4. FSRS를 플래시카드 밖(노트·문서·레슨)에서 쓰는 사례와 통합 패턴
### Takeaway
FSRS는 콘텐츠 무관 상태 전이 함수라 노트/아티클 단위 복습 사례가 다수(Obsidian Note SR, Logseq, Org-srs, SiYuan, Foliole/ZKMemo/Bundle 증분 읽기). "코스 레슨"을 FSRS로 재방문 스케줄링하는 전용 오픈소스 플랫폼은 찾지 못했고, 가장 가까운 선례는 노트 단위 리뷰다.
### Cited Findings
- awesome-fsrs 응용: Logseq(cljc-fsrs), Obsidian obsidian-spaced-repetition-recall/HiNote/LearnKit(FSRS-6, "brings flashcards, note review, tests, and AI-assisted study tools into Obsidian")/True Recall, Org-srs/Org-fc(FSRS-6 실험), RemNote(4.5), SiYuan(5), TiddlyWiki, ZKMemo("combines FSRS-based spaced repetition with incremental reading"); 증분 읽기 Foliole("Native incremental reading with integrated FSRS scheduling", ts-fsrs), Bundle("read-later app ... helps you remember what you read"); 코스형 Japanese Learning("a web course ... lessons on kana, vocabulary, kanji and grammar", py-fsrs), BiliMind Desktop("turns a folder of lecture slides, past exam papers or notes into a course", ts-fsrs 5.4.2, AGPL-3.0); 라이선스 표기 예 Etude(MIT), Jiaci(MIT), Ordkort(AGPL-3.0), Read Frog(GPLv3) — [awesome-fsrs](https://github.com/open-spaced-repetition/awesome-fsrs)
- Obsidian "Note Spaced Repetition": 카드가 아니라 노트 전체를 FSRS/SM-2로 리뷰 — [Obsidian plugin](https://community.obsidian.md/plugins/note-spaced-repetition)
- (2차) FSRS는 "content-agnostic and deck-agnostic"이라 이식이 쉽지만 모델 적합도는 다소 낮아진다는 의견 — [HN 44790422](https://hn.svelte.dev/item/44790422)
- API 재확인: py-fsrs `review_card(card, rating)`→`(card, review_log)`, `Optimizer(review_logs)` — [py-fsrs](https://github.com/open-spaced-repetition/py-fsrs); ts-fsrs `DefaultScheduler().review({card, grade, now})` — [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs); Anki 지침(학습 단계 1일 미만, 옵티마이저 월 1회, retention 0.9) — [Anki manual](https://docs.ankiweb.net/deck-options.html)
### Inferences
- 레슨 단위 통합 패턴(추론): 복습 단위=레슨 UUID 또는 레슨 내 knowledge-check 문항; 최초 완료 시 `newCard`, due 도달 시 요약/퀴즈 + Again/Hard/Good/Easy → `review` → `{s,d,decay,due,last_review}` 갱신 + review_log 추가; desired retention 코스 기본 0.9·사용자 오버라이드; 파라미터는 사용자당 1벌로 시작해 월 1회 `Optimizer`; 평점 1–4 유지. "레슨 1개=카드 1장"은 신호가 거칠므로 Exercism식 "개념" 단위 복습 아이템이 중간안. 다중 사용자 서버에서는 Obsidian식 frontmatter 상태 저장 대신 DB 저장 + Git 콘텐츠 분리.
### Gaps
- 인증·다중 사용자를 갖춘 "레슨 FSRS" 전용 오픈소스 플랫폼 미발견; Japanese Learning/BiliMind 상세·라이선스 미열람; 레슨 단위 FSRS 효과 연구 없음(Duolingo half-life regression은 별개 알고리즘); FSRS-7의 모델 가정 변화 미확인.
