# ROS 2 and Robotics-Software Learning Materials (state as of 2026-11-11)

Scope note: research conducted 2026-11-11. docs.ros.org and ros.org/reps are behind Anubis bot-protection, so official ROS docs were read via the GitHub source (`ros2/ros2_documentation`, `ros-infrastructure/rep`) and the `repo.test.ros2.org` mirror; the content is identical to the rendered site. ## Key Question 1 — Current ROS 2 distributions (late 2026), EOL, platforms, which to target; is ROS 1 EOL?

### Takeaway
As of November 2026 there are three supported ROS 2 distributions: Lyrical Luth (LTS, released 22 May 2026, EOL May 2031, Tier-1 on Ubuntu 26.04), Jazzy Jalisco (LTS, EOL May 2029, Tier-1 on Ubuntu 24.04) and Humble Hawksbill (LTS, EOL May 2027, Ubuntu 22.04); Kilted Kaiju (non-LTS) expires Nov/Dec 2026. ROS 1 is fully EOL (Noetic ended 31 May 2025). The practical curriculum target is Jazzy on Ubuntu 24.04 (where almost all 2024–2026 courses, books and vendor robots sit), with a "works on Lyrical" note, because Lyrical tutorials are still scarce and it requires Ubuntu 26.04.

- ROS 1: "ROS Noetic End-of-Life: May 31, 2025" — the ROS PMC set Noetic (last ROS 1 release) EOL to 31 May 2025, matching Ubuntu 20.04 standard support; no further features, security fixes or binaries; recommended migration targets were Humble or Jazzy — [Open Robotics Discourse announcement](https://discourse.openrobotics.org/t/ros-noetic-end-of-life-may-31-2025/43160)
- Canonical offers Ubuntu Pro "ESM for ROS" giving Noetic security patches for up to 5 years after EOL as a stopgap — [Canonical blog: ROS Noetic is EOL](https://canonical.com/blog/ros-noetic-is-eol-take-action-to-maintain-fleet-security); [How to enable ESM for ROS](https://discourse.openrobotics.org/t/how-to-enable-esm-for-ros-and-ubuntu-to-keep-your-robots-supported-after-noetic-eol/49863)
- Gazebo Classic also reached EOL in 2025; modern Gazebo (gz-sim) is the simulator to teach — [Canonical blog](https://canonical.com/blog/ros-noetic-is-eol-take-action-to-maintain-fleet-security); migration guide for packages still using Gazebo Classic — [Gazebo docs: Migrating ROS 2 packages that use Gazebo Classic](https://gazebosim.org/docs/all/migrating_gazebo_classic_ros2_packages/)

- Nav2 support matrix: Rolling (development), Lyrical (Active Support), Kilted (Maintained), Jazzy (Active Support), Humble (Maintained), Iron/Galactic EOL — [docs.nav2.org/rolling](https://docs.nav2.org/rolling/index.html)
- ros2_control publishes stable docs for Lyrical (latest), Kilted, Jazzy and Humble — [control.ros.org getting started](https://control.ros.org/rolling/doc/getting_started/getting_started.html); a dedicated "ros2_control in Lyrical Luth: what's new" thread exists — [Discourse](https://discourse.openrobotics.org/t/ros2-control-in-lyrical-luth-whats-new/59593.md)
- micro-ROS `micro_ros_setup` supports Humble, Jazzy, Kilted, Lyrical and Rolling (Foxy/Galactic/Iron EOL) — [micro_ros_setup README](https://github.com/micro-ROS/micro_ros_setup)

### Inferences
- A beginner→intermediate curriculum launched late 2026 should be written against **Jazzy on Ubuntu 24.04** (EOL May 2029 covers a multi-year curriculum life; nearly every 2024–2026 course, book and reference robot targets Jazzy) and carry a short "Lyrical differences" appendix (Ubuntu 26.04, `AsyncNode`, executor changes, ros2_control API removals). Switching the primary target to Lyrical makes sense once the major third-party courses/books re-release for it (none found yet as of Nov 2026, other than Automatic Addison starting Lyrical-labelled posts).
- Humble should be mentioned only as a legacy target (many hardware vendors still ship it, EOL May 2027); Kilted should not be targeted (EOL within weeks of Nov 2026).
- ROS 1 can be treated as historical; no ROS 1 content is needed beyond a one-paragraph "why ROS 2" note.

### Gaps
- The REP 2000 master source fetched did not yet contain a Lyrical section (the docs supported-platforms page was used instead); the REP may lag the docs.
- Kilted's exact EOL is given as "December 2026" on the Releases page and "November 2026" in REP 2000 — minor conflict, both sources official.
- I did not find a published Lyrical adoption statistic (e.g., package counts per distro) to quantify how far the ecosystem has moved.

## Key Question 2 — Best structured ROS 2 learning paths (official docs, The Construct, Articulated Robotics, Robotics Back-End/Udemy, Automatic Addison, books)

### Takeaway
The strongest free spine is the official docs tutorial ladder (CLI tools → client libraries → intermediate) plus Automatic Addison's Jazzy text tutorials; the strongest paid spines are Edouard Renard's Udemy ladder (Level 1→3, then Nav2/MoveIt 2/ros2_control, Jazzy, ~$12–13 on sale) and The Construct's browser-based platform (free Basic tier; Learner €39.97/mo or €439/yr). Of the books, "ROS 2 from Scratch" (Renard, Packt 2024, Jazzy) is the best beginner text; "A Concise Introduction to Robot Programming with ROS 2" 2nd ed. (Martín Rico, CRC 2025) and "Mastering ROS 2 for Robotics Programming" 4th ed. (Joseph & Cacace, Packt July 2025, Jazzy) cover intermediate. Articulated Robotics is still excellent for concepts but its written series is Foxy-era.

### Cited Findings

**Official ROS 2 docs tutorials (free, text, EN, Jazzy/Kilted/Lyrical selectable)**
- Tutorial ladder: *Beginner: CLI tools* — Configuring environment; Using turtlesim, ros2 and rqt; Understanding nodes/topics/services/parameters/actions; rqt_console; Launching nodes; Recording and playing back data. *Beginner: Client libraries* — colcon; workspace; package; pub/sub (C++ and Python); service/client (C++/Python); custom msg/srv; custom interfaces; parameters in a class (C++/Python); ros2doctor; plugins (C++). *Intermediate* — rosdep; actions (create, server/client C++/Python); composable nodes; node interfaces template; parameter monitoring; Launch; tf2; Testing; URDF; RViz. *Advanced* — topic statistics; Fast DDS discovery server; custom allocator; ament lint; dynamic discovery; rosbag from node (C++/Python); reading bags; ros2_tracing; Simulators; Security. *Demos* — QoS for lossy networks; managed lifecycles; intra-process comms; real-time programming; dummy robot; logging; content-filtering subscription; service introspection — [Jazzy Tutorials index (mirror)](https://repo.test.ros2.org/en/jazzy/Tutorials.html); canonical URL [docs.ros.org/en/jazzy/Tutorials.html](https://docs.ros.org/en/jazzy/Tutorials.html)

## Key Question 6 — Tooling/environment advice for learners (Ubuntu vs Docker vs WSL2 vs macOS; RViz, Foxglove, rosbag) and 2025–2026 community guides

### Takeaway
Community consensus (Discourse/Reddit 2024–2026) is native Ubuntu (24.04 for Jazzy) first; Docker is the best portable alternative (Docker's official ROS 2 guide; Articulated Robotics "Docker for Robotics"; Nav2 "Docker for Development: Zero to Hero"), with macOS needing XQuartz and lower performance; WSL2 is workable but repeatedly reported as friction-prone. Workspace/sourcing errors are the #1 beginner time sink (instructors report "a week each semester"), so curricula increasingly ship pre-built containers/startup scripts. For visualization, RViz remains the default; Foxglove is the modern complement (free plan 3 seats/10 GB/5 devices, closed source since 2.0) and MCAP is the rosbag2 default since Iron.

### Cited Findings
- Native Ubuntu: a Discourse poster who tried macOS, Windows, WSL2 and native Ubuntu "concluded that a dedicated Ubuntu setup is best for a beginner wanting to learn ROS end to end"; another found "WSL2 while very cool and convenient has just got in the way" — [Is WSL Sufficient for Learning and Using ROS?](https://discourse.openrobotics.org/t/is-wsl-sufficient-for-learning-and-using-ros/42700); Reddit r/ROS (Apr 2025) thread on containerised Humble for WSL2 with a commenter urging native install after seeing learners struggle with WSL2 — [r/ROS mirror](https://redlib.ssps.io/r/ROS/comments/1jp6f35/containerised_ros_2_humble_for_windows_wsl2)
- Docker: Docker's official guide "Introduction to ROS 2 Development with Docker" uses the `ros:humble` image (switchable to `jazzy`/`rolling`), covers a Compose dev container and a Turtlesim example; Linux `xhost +local:docker`; macOS requires XQuartz with network clients enabled; no Windows GUI guidance — [docs.docker.com/guides/ros2](https://docs.docker.com/guides/ros2/); a university ROS 2 course states "for Mac users, the best option … is by using Docker, but please note that performance is not optimal" — [tom-howard COM2009 Docker ROS 2](https://tom-howard.github.io/com2009/ros/other-options/docker-ros2); Nav2 ships a "Docker for Development: Zero to Hero" tutorial and a VS Code dev container — [docs.nav2.org](https://docs.nav2.org/rolling/index.html); Articulated Robotics "Docker for Robotics" series — [category](https://articulatedrobotics.xyz/tutorials); 2b-t/docker-for-robotics best-practices guide (Docker GUIs on Linux and Windows/WSL2) — [listing](https://awesome.ecosyste.ms/projects/github.com%2F2b-t%2Fdocker-for-robotics)
- WSL2 upside: "WSL2 supports NVIDIA GPU passthrough", preferred over VMware/VirtualBox by one robotics setup guide — [av1tenth docs](https://av1tenth-docs.readthedocs.io/en/latest/gettingstarted/installingubuntu.html)
- The Construct avoids the whole problem by running ROS in the browser ("no ROS setup is required") — [course page](https://theconstruct.ai/?p=25563)
- Beginner pain points (Sept–Oct 2026 thread): instructor Prasad_Prabhu: students "lose about a week each semester to workspace and sourcing problems before they write any robot code" ("package not found", `--symlink-install`, per-terminal sourcing); peci1's course uses a startup script that builds/sources inside an Apptainer image and has students fill TODOs in provided packages ("I was long opposing this approach, but in the end I agree"); madsdyson: break the setup on purpose (delete `install/`, forget to source) and read the errors; verify against your install with `ros2 interface show` / `ros2 pkg prefix` — [Discourse](https://discourse.openrobotics.org/t/what-is-the-hardest-part-of-learning-ros-2-as-a-beginner/57917)
- Reddit July 2025 "How to start with ROS2": commenters recommend the official docs ("I've learnt using ros2 through that way only") and "just start building something"; a warning that "some packages are still not updated for Jazzy" — [r/ROS mirror](https://reddit.zackpollard.pro/r/ROS/comments/1m5d854/how_to_start_with_ros2)
- Foxglove: official ROS docs page "Visualizing ROS 2 data with Foxglove" (Lyrical) — [docs.ros.org](https://docs.ros.org/en/lyrical/Related-Projects/Visualizing-ROS-2-Data-With-Foxglove.html); Foxglove free plan: 3 developer seats, 10 GB cloud storage, 5 connected devices (a 2025 comparison says 10 devices — check pricing page); academic users get free access; Foxglove Bridge auto-subscribes all topics for live viewing; plays `.mcap` and `.db3` (db3 lacks message definitions, so custom types can fail) — [Foxglove ROS 2 docs](https://docs.foxglove.dev/docs/connecting-to-data/frameworks/ros2); "from Iron, ros2 bag records to MCAP by default" — [Foxglove ROS 2 getting started](https://docs.foxglove.dev/docs/getting-started/ros2); Foxglove 2.0 (2024): "1.x source code remains available on GitHub, but our future development will be closed source" — [Discourse](https://discourse.openrobotics.org/t/foxglove-2-0-integrated-ui-new-pricing-and-open-source-changes/36583); RViz vs Foxglove vs Rerun comparison — [foxglove.dev](https://foxglove.dev/robotics/rviz-vs-foxglove-vs-rerun); "best tools for rosbag visualization in 2025" — [foxglove.dev](https://foxglove.dev/robotics/the-best-tools-for-rosbag-visualization-in-2025)
- rosbag2 in Lyrical: Python record/playback API, remote record/stop services, `--max-bag-files` circular recording, message-loss events; `ros2 doctor --report` expanded — [Release-Lyrical-Luth.rst](https://raw.githubusercontent.com/ros2/ros2_documentation/rolling/source/Releases/Release-Lyrical-Luth.rst)
- Official tutorials covering tooling: "Recording and playing back data", "Using rqt_console", "Using ros2doctor", RViz and tf2 tutorials, ros2_tracing — [Jazzy tutorials index](https://repo.test.ros2.org/en/jazzy/Tutorials.html)
- AI-assistant caveat for learners: give tools "the exact error, your package files, and your distro, since most bad answers come from it guessing Humble" — [Discourse](https://discourse.openrobotics.org/t/what-is-the-hardest-part-of-learning-ros-2-as-a-beginner/57917)

### Inferences
- The curriculum should (a) prescribe Ubuntu 24.04 native or dual-boot as the primary path, (b) provide an official-image-based Docker Compose dev container (`ros:jazzy`) as the equal-footing alternative for macOS/Windows users, (c) include a dedicated "workspace & sourcing" lesson with deliberate breakage exercises, and (d) teach RViz first, Foxglove + MCAP second.
- Because many 2025–2026 learner problems come from distro mismatch (Humble-era answers applied to Jazzy/Lyrical), every lesson should state its distro and apt package names explicitly.

### Gaps
- No formal 2025–2026 head-to-head benchmark of Ubuntu vs Docker vs WSL2 vs macOS was found; evidence is forum anecdote.
- Foxglove's current (Nov 2026) free-plan limits should be re-verified on foxglove.dev/pricing (sources conflict on 5 vs 10 devices).
- The exact release date of Foxglove 2.0 pricing changes was not captured (Discourse thread is from 2024).
