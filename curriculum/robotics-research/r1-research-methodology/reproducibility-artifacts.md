# 재현성과 아티팩트

## 도달 목표

**"내 컴퓨터에서는 됩니다"는 연구 결과가 아니다.** 이 레슨은 제3자가 당신의 저장소를 받아
한 명령으로 논문의 표와 그림을 다시 만들 수 있게 하는 작업을 훈련한다.

재현성은 선의가 아니라 **기술**이다. 환경 고정, 난수 통제, 데이터 출처 기록, 산출물 생성
자동화, 라이선스와 DOI — 각각 구체적인 절차가 있다. 그리고 이것은 남을 위한 일이기 전에
**6개월 뒤의 자신**을 위한 일이다. 재현 불가능한 저장소를 가진 연구자는 리뷰어의 추가 실험
요청에 답할 수 없다.

산출물: **재현 가능한 저장소 + 아티팩트 체크리스트**.

## 시작 전 자가 진단

| 질문 | 할 수 있으면 | 못 하면 |
|---|---|---|
| 6개월 전 자기 실험을 지금 그대로 재현할 수 있는가? | 절차 3단계부터 | 1단계부터 — 그게 이 레슨의 이유다 |
| 락파일(lockfile)과 `requirements.txt` 의 차이를 말할 수 있는가? | 1단계를 빠르게 | `uv` 문서의 Locking and syncing 을 먼저 읽는다 |
| GPU 에서 같은 시드로 두 번 돌려 비트 단위로 같은 결과가 나오는가? | 2단계를 빠르게 | 2단계를 정독한다 — 대부분 "아니오"다 |
| 자기 코드의 라이선스를 아는가? | 5단계를 빠르게 | 5단계 정독 — 라이선스 없는 공개는 사실상 사용 금지다 |

## 절차

**1단계 — 환경을 고정한다 (2시간).** 세 층을 모두 고정한다:
- **의존성**: 락파일을 커밋한다(`uv.lock`). 실행은 `uv run --locked` 로 해서 락파일이 낡으면
  **실패하게** 만든다. `requirements.txt` 의 범위 지정(`>=`)은 고정이 아니다.
- **시스템**: 컨테이너 이미지(`Dockerfile`)로 OS·CUDA·드라이버 수준을 기록한다. 이미지는
  다이제스트(`@sha256:...`)로 핀을 박는다.
- **하드웨어**: GPU 모델, CPU, RAM 을 README 에 적는다. 수치 결과가 하드웨어에 의존할 수 있다.

**2단계 — 난수와 비결정성을 통제한다 (2시간).** 둘은 다른 문제다:
- **시드**: Python·NumPy·프레임워크의 시드를 **하나의 함수에서** 모두 설정하고, 사용한 시드를
  결과 파일에 기록한다. 시드를 고정하는 것과 **여러 시드로 돌리는 것**은 모순이 아니다 —
  시드 목록(예: 0–9)을 설정으로 고정하고 전부 돌린다.
- **비결정적 연산**: GPU 의 원자적 누적(atomic add), 비결정적 커널, 병렬 데이터 로더 순서는
  시드로 잡히지 않는다. 결정론 모드를 켤 수 있으면 켜고(성능 대가가 있다), 못 켜면 **"비트 단위
  재현은 보장되지 않고 통계적 재현만 보장한다"**고 명시한다.
- 실기 로봇은 **원리적으로 비결정적**이다(마찰, 온도, 배터리). 이때 재현성의 단위는 한 번의 실행이
  아니라 **분포**다: 시행 수와 신뢰구간으로 재현한다(이전 레슨).

**3단계 — 산출물 생성을 자동화한다 (3시간).** 목표는 **한 명령**이다:

```
make all     # 또는 python -m scripts.reproduce --all
```

- 원자료(raw) → 중간 결과 → 표·그림의 경로를 스크립트로 고정한다. 손으로 엑셀에 붙여 만든
  표는 재현 불가능하다.
- 논문의 **각 표와 그림에 생성 스크립트를 1:1로 대응**시킨다(`figures/fig3.py` → `fig3.pdf`).
- 비용이 큰 실험은 **두 경로**를 제공한다: 전체 재현(`--full`, 며칠)과 축소 재현(`--smoke`,
  10분). 축소 경로가 없으면 아무도 확인하지 않는다.
- 캐시된 중간 결과를 저장소에 함께 넣되, 원자료에서 그것을 만드는 스크립트도 함께 넣는다.

**4단계 — 데이터와 모델의 출처를 기록한다 (2시간).** 데이터셋 이름만 적는 것은 부족하다:
버전·다운로드 날짜·전처리 스크립트·분할(split) 정의 파일을 모두 기록한다. 공개 데이터는 URL 과
체크섬, 비공개 데이터는 **왜 공개할 수 없는지와 대체 경로**를 적는다. 사전학습 가중치는
출처와 라이선스를 적는다 — 모델 가중치의 라이선스는 코드 라이선스와 다를 수 있다.

**5단계 — 라이선스와 공개 범위를 정한다 (1.5시간).** **라이선스 파일이 없는 공개 저장소는
법적으로 사용 허가가 없는 코드다.** 코드는 허용적 라이선스(Apache-2.0, MIT)를 기본으로 하고,
데이터·문서는 CC BY 계열을 쓴다. 소속 기관의 규정과 공동저자 동의를 먼저 확인한다. 공개가
제한되면(기업 데이터, 안전 문제) **무엇을 왜 공개하지 못하는지** 논문에 적는다 — 침묵보다 낫다.

**6단계 — DOI 로 고정하고 체크리스트로 점검한다 (1.5시간).** 저장소 스냅숏에 DOI 를 받아
(예: Zenodo 의 GitHub 연동) 논문이 **특정 커밋**을 인용하게 만든다. 그다음 아티팩트 체크리스트로
자기 저장소를 점검한다: ⓐ 받아서 설치되는가 ⓑ 축소 경로가 10분 안에 끝나는가 ⓒ 표·그림이
재생성되는가 ⓓ 수치가 논문과 일치하는가 ⓔ 라이선스·인용 정보가 있는가.
**가장 확실한 점검은 동료에게 빈 환경에서 돌려 보게 하는 것이다.**

## 판정 기준

| 항목 | 통과 | 우수 |
|---|---|---|
| 환경 고정 | 락파일이 커밋되어 있다 | 컨테이너 다이제스트 핀 + `--locked` 실행 + 하드웨어 명시 |
| 난수 통제 | 시드를 설정하고 기록한다 | 비결정적 연산을 분리해 명시하고, 여러 시드의 분포로 보고 |
| 산출물 자동화 | 스크립트로 주요 결과를 생성한다 | 표·그림이 1:1 스크립트 대응 + 축소 경로(10분) 제공 |
| 데이터 출처 | 데이터셋과 분할이 명시된다 | 버전·체크섬·전처리 스크립트·비공개 사유까지 기록 |
| 라이선스 | LICENSE 파일이 있다 | 코드·데이터·가중치 각각의 라이선스와 제약을 구분해 기록 |
| 외부 검증 | 본인이 빈 환경에서 재현했다 | 제3자가 저장소만 받아 재현했고 그 로그를 공개 |

## 실패 사례

- **락파일 없이 `requirements.txt` 만 둔다.** 반년 뒤 상위 버전이 설치되어 결과가 달라진다.
- **시드를 고정했다고 재현된다고 믿는다.** GPU 비결정성은 시드로 잡히지 않는다.
- **표를 손으로 만든다.** 숫자 하나가 바뀌면 전부 다시 해야 하고, 그 과정이 기록되지 않는다.
- **축소 경로가 없다.** 전체 재현이 3일이면 리뷰어도 후속 연구자도 확인하지 않는다.
- **LICENSE 가 없다.** 공개했지만 아무도 합법적으로 쓸 수 없다.
- **데이터 분할을 코드에 하드코딩하고 파일로 남기지 않는다.** 분할이 바뀌면 비교가 깨진다.
- **"코드는 요청하면 제공"이라고 쓴다.** 실제 응답률은 낮고, 저자가 이직하면 사라진다.
- **실기 결과를 단일 실행으로 제출한다.** 실기는 분포로 재현해야 한다.

## 사례 연구

**필독 1편 + 공개 저장소 2개 감사.**

**Pineau et al. (2021)** — `표준`. NeurIPS 2019 재현성 프로그램의 보고서다. 질문:
ⓐ 재현성 체크리스트가 요구하는 항목은 무엇이고 각 항목이 어떤 실패를 막는가?
ⓑ 코드 제출이 **의무가 아닌데도** 제출률이 높아진 이유로 저자들이 든 것은?
ⓒ 저자들이 측정한 재현성의 지표는 무엇이고, 그 한계는?
ⓓ 이 체크리스트를 **실기 로보틱스**에 적용하면 어떤 항목이 추가로 필요한가?

**저장소 감사**: 자기 분야의 유명 논문 2편의 공개 저장소를 받아 §판정 기준 여섯 항목으로
점수를 매긴다. 실제로 설치하고 축소 실행까지 시도하고, **막힌 지점과 걸린 시간**을 기록한다.
이 경험이 자기 저장소 설계를 바꾼다. (한 편은 재현이 쉬웠던 것, 한 편은 어려웠던 것을 고른다.)

## 산출물 과제

**산출물 1 — 재현 가능한 저장소**
- 락파일 + 컨테이너 정의 + 시드 설정 함수 + 산출물 생성 스크립트 + LICENSE + README.
- README 에: 한 줄 설치, 축소 실행 명령(10분), 전체 실행 명령과 예상 시간, 하드웨어, 데이터 획득 절차.
- **수용 기준**: ⓐ 빈 가상환경에서 설치부터 축소 실행까지 **문서만 보고** 성공 ⓑ 축소 실행이
  10분 이내 ⓒ 주요 표 1개와 그림 1개가 스크립트로 재생성되고 값이 일치.

**산출물 2 — 아티팩트 체크리스트** (1–2페이지)
- §판정 기준 여섯 항목을 자기 저장소에 적용한 자기 평가표. 각 항목에 **증거**(명령, 로그 경로)를 단다.
- 통과하지 못한 항목은 **왜 못 하는지와 대신 무엇을 보장하는지** 적는다(예: 비트 단위 재현 불가 →
  10시드 분포 재현).

**산출물 3 — 교차 재현 로그** (1페이지)
- 남의 저장소 2개를 재현하려 한 기록: 막힌 지점, 해결/포기, 걸린 시간.
- 그로부터 자기 저장소에 **반영한 변경 3개**를 적는다.

**수용 기준**: 세 산출물이 §판정 기준에서 모두 통과 이상, 그리고 **제3자(동료 1명)가 산출물 1을
빈 환경에서 재현**했다.

## 열린 문제

- **(열린 문제) 실기 로보틱스의 재현성 단위** — 하드웨어·환경이 다르면 같은 코드도 같은 결과를
  내지 않는다. 무엇을 "재현됨"으로 볼지(분포 일치? 순위 일치? 경향 일치?)에 합의가 없다.
- **(열린 문제) 대규모 모델의 재현 비용** — 학습에 수천 GPU 시간이 드는 결과는 원리적으로
  재현 검증이 불가능하다. 부분 재현이나 증명 가능한 학습 로그 같은 대안이 정립되지 않았다.
- **(열린 문제) 아티팩트 평가의 인센티브** — 아티팩트 검증은 노동집약적이고 보상이 적다.
  로보틱스 학회에서 지속 가능한 검증 체계를 만드는 문제가 열려 있다.
