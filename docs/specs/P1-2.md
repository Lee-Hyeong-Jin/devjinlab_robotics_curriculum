## 목표

레슨 본문의 ```` ```quiz ```` 블록(YAML)으로 정의한 객관식·다중선택·단답·O/X 문항을 터미널에서
풀고 즉시 채점·해설을 보여준다. 오답과 `card: true` 문항은 플래시카드가 되고, `rc review` 가
SM-2 로 계산한 복습 일정(next due)에 따라 카드를 제시한다. 기록은 기존 SQLite 진도 저장소에
스키마 v2 로 추가하고, JSON 내보내기/가져오기·주간 리포트·정적 사이트에 반영한다.

## 범위 밖

- FSRS(Phase 2 검토, ADR 0005), 개념 카드(`source=concept`, 작성자 지정 핵심 개념 카드)는
  콘텐츠 모델 확장이 필요하므로 후속 마일스톤. Phase 1 카드는 퀴즈 유래(`source=quiz`)뿐이다.
- Activity 단위 진도(`activity_progress`), 사이트에서 직접 퀴즈 풀기(정적 사이트는 문항만 표시).
- 기존 `curriculum/` 레슨 본문에 퀴즈 블록 추가(콘텐츠 담당 세션의 일). 샘플은 테스트 픽스처에만.

### 퀴즈 블록 (설계 §3.4 그대로)

````markdown
```quiz
- id: q1
  type: single            # single | multi | short | truefalse
  prompt: "DH 변환 A_i 를 이루는 기본 변환의 곱 순서는?"
  choices: ["Rot_x·Trans_x·Trans_z·Rot_z", "Rot_z·Trans_z·Trans_x·Rot_x", "Trans_z·Rot_z·Rot_x·Trans_x"]
  answer: 1               # 0-based; multi 는 리스트; short 는 허용 답 리스트; truefalse 는 bool
  explanation: "관절축(z) 기준 회전·이동 뒤 링크축(x) 기준 이동·회전."
  card: true              # 맞혀도 플래시카드로 만들지 (기본 false)
```
````

- 한 레슨에 블록이 여러 개여도 되며 순서대로 이어 붙인다. 문항 `id` 는 레슨 안에서 유일한 슬러그.
- `single`/`multi`: `choices` 2개 이상, `answer` 는 0-based 인덱스(범위 검사). `multi` 는 중복 없는 리스트 1개 이상.
- `short`: `answer` 는 비어 있지 않은 문자열 리스트(허용 답). 비교는 trim·소문자·공백 축약 후 일치.
- `truefalse`: `answer` 는 bool. 입력은 `o/x`, `t/f`, `true/false`, `y/n`, `참/거짓`, `예/아니오` 허용.
- 터미널 입력: `single` 은 1-based 번호, `multi` 는 쉼표·공백 구분 번호 집합.
- `activities[]` 의 `kind: quiz` 항목은 시간 추정·활동 체크용 **메타**이고, 본문 퀴즈 블록이 **실체**다.
  블록 없는 레슨에 `rc quiz` 를 실행하면 오류(종료 코드 1).

### 카드와 SM-2

- 카드 id `"<lesson_id>-quiz-<qid>"`, `front` = 문항(선택지 포함), `back` = 정답 + 해설, `source=quiz`.
  오답 또는 `card: true` 문항을 풀 때마다 생성(이미 있으면 유지, 상태 초기화 안 함).
- `card_state(card_id, user_id, repetitions, interval_days, ease, due)`; 새 카드는 `repetitions=0,
  interval_days=0, ease=2.5, due=오늘`.
- SM-2(설계 §5, q = again 1 / hard 3 / good 4 / easy 5):
  `q < 3` → repetitions 0, interval 1; 그 외 repetitions+1, interval 1 → 6 → round(interval × ease);
  ease = max(1.3, ease + 0.1 − (5−q)(0.08 + (5−q)·0.02)); due = today + interval.
- `rc review` 세션에서 `again` 카드는 세션 끝에 다시 제시(최대 2회). 모든 응답은 `reviews` 에 기록.

### 저장소 스키마 v2

```sql
cards(id TEXT PK, user_id, lesson_id, question_id, front, back, source, created_at, suspended)
card_state(card_id TEXT, user_id, repetitions, interval_days, ease, due, PRIMARY KEY(card_id, user_id))
reviews(id PK, card_id, user_id, reviewed_at, rating, interval_before, interval_after, ease_after)
quiz_attempts(id PK, user_id, lesson_id, question_id, answered_at, answer, correct)
```

`ProgressExport.schema_version` 은 2 가 되고 `cards`, `card_states`, `reviews`, `quiz_attempts`
목록이 추가된다(기본값 빈 리스트 → v1 내보내기 파일도 가져올 수 있다).

## 열린 질문

- 카드 재생성 정책: 같은 문항을 다시 틀려도 기존 카드 상태를 유지한다(보수적). 리셋이 필요하면 후속.
- 개념 카드(`card: true` 가 아닌 작성자 지정 핵심 개념)는 콘텐츠 모델 변경이 필요해 PM 결정 후 진행.
