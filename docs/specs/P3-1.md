# P3-1 관리자 콘솔 운영 기능

## 배경

P2-4 의 관리자 화면은 두 장이다: 사용자 표(역할·상태 변경, 강제 로그아웃)와 감사 로그 표.
운영자가 실제로 묻는 질문에 답하지 못한다.

| 운영자의 질문 | 지금 |
|---|---|
| 지금 서비스가 어떤 상태인가? 가입·로그인 실패가 늘었나? | 볼 곳이 없다 |
| 이 이메일의 사용자를 찾아라 | 50명씩 넘겨 가며 눈으로 찾는다 |
| 이 사람이 로그인이 안 된다는데 무슨 일인가? | 세션·토큰·인증 상태·최근 기록을 볼 수 없다 |
| 계정이 탈취된 것 같다 | 세션은 끊을 수 있지만 API 토큰은 못 끊는다 |
| 지난주 권한 변경을 누가 했나 | 감사 로그를 처음부터 넘겨 본다. 내보낼 수도 없다 |

## 범위

API (`/api/v1/admin`, 전부 `admin` 역할·`admin` PAT 범위):

- `GET /overview` — 사용자 집계, 14일 가입 추이, 로그인 성공·실패(24시간·7일), 활성 세션 수, 학습
  활동(7일 활성 학습자·완료 레슨·학습 시간), 시스템 상태(버전, 레슨 수, 메일·공개 설정, 감사 보존 기간),
  확인이 필요한 항목(비활성·삭제 예정·오래된 미인증 계정).
- `GET /users` — `q`(이메일·표시 이름 부분 일치), `role`, `status`, `verified` 필터와 `total`.
- `GET /users/{id}/overview` — 사용자, 활성 세션, API 토큰(해시·값 없음), 외부 로그인, 학습 요약,
  최근 24시간 로그인 실패 수, 이 사용자가 행위자이거나 대상인 최근 감사 기록.
- `DELETE /users/{id}/tokens` — API 토큰 전부 폐기.
- `POST /users/{id}/password-reset` — 재설정 메일 발송(메일 미설정이면 503, 비활성 계정이면 409).
- `GET /audit` — `action`(접두어), `actor_user_id`, `target_type`, `target_id`, `since`, `until` 필터.
  항목에 행위자 이메일을 붙인다.
- `GET /audit/export` — 같은 필터의 CSV(최대 10,000행, 수식 주입 방지).

웹: `/admin`(개요), `/admin/users`(검색·필터), `/admin/users/{id}`(상세·조치), `/admin/audit`(필터·CSV).

## 범위 밖

- 관리자의 계정 삭제·사용자 생성·초대, 사용자 가장(impersonation): 되돌리기 어렵거나 감사 설계가
  따로 필요하다.
- 콘텐츠 편집: 콘텐츠의 원본은 저장소다(PRD).
- 실시간 차트·외부 모니터링 대체: `/metrics`(Prometheus)가 그 역할이다. 개요는 DB 에서 읽는 요약이다.

## 설계 결정

- **스키마 변경 없음.** 모든 집계는 기존 표(`users`, `sessions_auth`, `login_attempts`, `audit_log`)와
  진행도 저장소의 조회로 만든다.
- **학습 집계는 순수 함수**(`learn/platform.py`)로 두고 API 는 저장소에서 읽은 행을 넘긴다. 전체 행을
  읽으므로 요청마다 O(행 수)다 — 이 플랫폼의 배포 규모(PRD: 동시 500명)에서는 충분하고, 그 이상이면
  집계 표가 필요하다(명세에 한계로 남긴다).
- **조회도 감사한다**(기존 규칙). 개요·상세·내보내기 각각 한 줄.
- **비밀번호 재설정은 메일로만.** 관리자가 비밀번호를 정하거나 링크를 보지 못한다.
- **CSV 수식 주입**: `=`, `+`, `-`, `@`, 탭, CR 로 시작하는 셀 앞에 `'` 를 붙인다(OWASP).
