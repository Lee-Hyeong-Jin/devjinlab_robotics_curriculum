# P3-2 운영 모니터링

결정과 근거는 ADR 0017. 여기에는 만들 것만 적는다.

## 수집

| 대상 | 어디서 | 저장 |
|---|---|---|
| API 요청 | `OpsMiddleware` (ASGI) → 버퍼 → 주기적 flush | `ops_request_stats` (시간 버킷·라우트·메서드·상태군) |
| 실패한 요청(5xx) | 같은 미들웨어, 즉시 | `ops_request_errors` |
| 방문 | 웹 미들웨어가 문서 요청마다 `POST /api/v1/telemetry/pageview` | `ops_page_views`, `ops_visitors`, `ops_referrers` |
| 시스템 자원 | 조회 시점에 읽음 | 저장 안 함 |

헬스체크(`/healthz`, `/readyz`, `/version`)와 `/metrics`, 수집 엔드포인트 자신은 요청 집계에서 뺀다
(프로브가 트래픽의 대부분이 되지 않게).

## API (`/api/v1/admin/monitoring`, admin 전용)

- `GET /system` — CPU(부하 평균, 코어 수, 사용률), 메모리, 디스크(데이터 디렉터리), 온도 센서 목록,
  호스트·프로세스 가동 시간, 프로세스 RSS, DB 종류·크기·ping 시간·풀, 그리고 임계값 판정.
- `GET /traffic?range=24h|7d|30d` — 요약(집계 단위가 1시간이라 그보다 짧은 기간은 없다. 24시간·7일은
  시간별, 30일은 일별 시계열),(요청 수, 성공률, 4xx·5xx 비율, p50·p95·p99, 평균)과
  버킷 시계열, 라우트별 상위(요청 수, 오류 수, p95).
- `GET /errors?limit&cursor&status&route` — 실패 기록, 최신순, 커서 페이지.
- `GET /visits?range=7d|30d|90d` — 일별 조회 수·순 방문자·봇 조회 수, 상위 페이지, 유입 호스트,
  언어·로그인 비율, 로그인 사용자 수(7일·30일).

## 웹

`/admin/monitoring` — 탭 없이 한 화면에 시스템 → 트래픽 → 실패 기록 → 방문 순. 기간은 URL 쿼리.
임계값을 넘으면 "확인이 필요한 항목"에 뜬다(개요 화면에도 한 줄).

## 임계값

| 지표 | 주의 | 위험 |
|---|---|---|
| 디스크 사용률 | 80% | 90% |
| 메모리 사용률 | 85% | 95% |
| 부하 평균(1분)/코어 | 1.0 | 2.0 |
| 온도 | 80°C | 90°C |
| 5xx 비율(선택 기간) | 1% | 5% |
| p95 지연 | 1초 | 3초 |
