# 0007. 서버 모드 진도 저장소: PostgreSQL + SQLAlchemy Core + psycopg 3 + Alembic

- 상태: accepted
- 날짜: 2026-11-11
- 관련: docs/adr/0003-progress-store-sqlite.md, docs/platform-design.md §4.5,
  docs/architecture/operations.md §5·§6, docs/PRD.md §7(가용성·확장성)·§9, 부록 C.4(AC-DB.1~3),
  harness/roadmap.yaml P2-3

## 맥락

Phase 2 서버 모드는 여러 사용자의 진도를 한 DB 에 두고, 스키마 변경을 롤백 가능한 마이그레이션으로
관리해야 한다(PRD §7). 로컬 모드는 0003 의 SQLite(`.rc/progress.db`)를 그대로 유지한다.
`ProgressService` 는 `ProgressStore` Protocol 에만 의존하므로(0003) 같은 Protocol 의 두 번째
구현을 추가하면 된다. Protocol 은 동기 메서드다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. SQLAlchemy Core 2.x + psycopg 3 (동기) + Alembic | Protocol 그대로(동기). 테이블 정의 한 곳을 Alembic autogenerate 가 비교. psycopg 3 는 SQLAlchemy 비동기 엔진도 지원 | 새 런타임 의존성 3개(선택 extra 로 격리) |
| B. SQLAlchemy Core + asyncpg | API 에서 네이티브 async | Protocol·서비스·CLI 를 async 로 바꾸거나 이중 구현 필요 |
| C. SQLAlchemy ORM | 모델 매핑 | 이미 pydantic 모델이 있어 이중 모델, 쿼리가 SQLite 구현과 대조하기 어려움 |
| D. psycopg 3 직접 + 수작업 SQL 마이그레이션 | 의존성 최소 | 롤백·autogenerate 검사 없음, PRD §7 의 Alembic 요구 불충족 |

## 결정

A 를 택한다(아키텍트와 합의, 설계 커밋 d795872).

- 구현: `src/robotics_curriculum/progress/postgres.py` 의 `PostgresProgressStore`. 테이블 정의는
  `progress/schema.py`(SQLAlchemy `MetaData`) 한 곳에 둔다.
- 의존성: optional extra `postgres` = `sqlalchemy>=2.0`, `psycopg[binary]>=3.2`, `alembic>=1.13`.
  로컬 모드 설치(`pip install robotics-curriculum`)에는 들어가지 않는다. dev 그룹에는 포함.
- 백엔드 선택: `progress/factory.py` 의 `open_store()`. `RC_DATABASE_URL` 이
  `postgresql://`·`postgres://`·`postgresql+…://` 이면 PostgreSQL, `sqlite:///경로` 면 그 SQLite 파일,
  없거나 비면 기존 SQLite(`RC_DATA_DIR/progress.db`). 그 밖의 스킴은 오류.
  `postgresql://` 은 `postgresql+psycopg://` 로 정규화한다. 이름은 `RC_DATA_DIR` 과 맞춰 `RC_` 접두사
  (개발 머신의 일반 `DATABASE_URL` 이 CLI 를 의도치 않게 서버 DB 로 돌리지 않게).
- 마이그레이션: Alembic. 스크립트는 패키지 안 `src/robotics_curriculum/progress/migrations/` 에 두고
  루트 `alembic.ini`(`script_location = robotics_curriculum.progress:migrations`)로 실행한다. 설치된 휠과
  컨테이너의 migrate 서비스에서도 같은 리비전을 쓰기 위해서다(오케스트레이터 브리프의 루트 `alembic/`
  대신). 리비전 계획: `0001_initial` = SQLite 스키마 v1(lesson_progress, sessions, meta),
  `0002` = 진도 v2(P1-2: cards, card_state, reviews, quiz_attempts, quiz_runs, activity_progress),
  `0003+` = 인증·감사(P2-2: users, identities, …) 와 학습 테이블 `user_id → users.id` FK.
  각 리비전은 `meta.schema_version` 을 SQLite `MIGRATIONS` 번호와 1:1 로 맞춘다. `downgrade` 필수.
- 타입 매핑: 시각 TEXT(ISO) → `TIMESTAMPTZ`, 날짜 → `DATE`, 0/1 INTEGER → `BOOLEAN`, REAL →
  `DOUBLE PRECISION`, AUTOINCREMENT → `BIGINT GENERATED BY DEFAULT AS IDENTITY`. CHECK 제약·부분
  유니크 인덱스(사용자당 열린 세션 1개)는 같은 이름으로 유지. 읽은 시각은 항상 UTC aware.
  명시 id 로 넣은 세션(가져오기) 뒤에는 identity 시퀀스를 `MAX(id)` 로 당겨 충돌을 막는다.
- 스토어를 열 때 기본으로 `alembic upgrade head` 를 실행한다(SQLite 의 열 때 마이그레이션과 같은 동작).
  운영에서 migrate 를 별도 단계로 돌리면 `migrate=False`. DB 버전이 코드보다 높으면 열기를 거부한다.
- 커넥션·트랜잭션: `Engine` 하나가 풀(`pool_size=5`, `max_overflow=10`, `pool_pre_ping`)을 가지며
  여러 스토어·스레드가 공유할 수 있다. 스토어 인스턴스는 스레드 간 공유하지 않는다(요청당 1개).
  `transaction()` 은 중첩 가능하고 가장 바깥 블록만 커밋/롤백한다. 블록 밖 호출은 호출마다 짧은
  트랜잭션.
- 데이터 이전: `factory.transfer(source, dest, mode=empty|replace|merge, user_id=None)`. 원본은 다른
  스토어(로컬 SQLite) 또는 JSON 내보내기. merge 는 레슨을 `(user_id, lesson_id)` 로 upsert 하고
  `(user_id, lesson_id, started_at)` 이 같은 세션은 건너뛴다(AC-DB.3 중복 방지). `user_id` 를 주면 모든
  레코드를 그 서버 계정으로 옮긴다.
- 테스트: 계약 테스트(`tests/test_progress_store_contract.py`)를 SQLite·PostgreSQL 에 파라미터화.
  PostgreSQL 은 `RC_TEST_DATABASE_URL`(CI 서비스 컨테이너) 또는 testcontainers(`postgres:16.13`),
  Docker 가 없으면 이유를 출력하고 skip. 마이그레이션 왕복·한 단계 down/up·autogenerate 차이 0 검사.
- 로컬 개발 DB: `docker-compose.yml` 의 `db` 서비스(postgres:16.13, healthcheck `pg_isready`, 볼륨
  `dbdata`, `127.0.0.1:5432`). 개발용 비밀번호는 `RC_DB_PASSWORD`(기본 `rc-dev-only`), 운영 compose 는
  P2-5 에서 Docker secret(`POSTGRES_PASSWORD_FILE`).

## 결과

- 얻는 것: 서비스 코드 변경 없이 서버 DB 사용, Alembic 롤백·드리프트 검사, 두 백엔드 동작 차이를
  같은 테스트로 감시.
- 잃는 것 / 감수하는 리스크: 스키마를 SQLite `MIGRATIONS` 와 Alembic 리비전 두 곳에 쓴다(번호 1:1 과
  계약 테스트로 보완). Docker 없는 환경에서는 PostgreSQL 테스트가 skip 되므로 CI 에 Postgres 서비스가
  필요하다.
- 후속 작업: `service.open_service()`·CLI 가 `factory.open_store()` 를 쓰도록 연결(service.py 담당),
  `rc progress transfer` 같은 CLI 명령, CI 에 Postgres 서비스 + `RC_TEST_DATABASE_URL`(DevOps),
  Alembic 0002(진도 v2, P1-2 머지 후).
