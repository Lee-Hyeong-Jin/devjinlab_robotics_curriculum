# 0002. 그래프 엔지니어링 방식의 개발 하네스 채택

- 상태: accepted
- 날짜: 2026-11-11
- 관련: harness/graph.md, docs/HARNESS.md, docs/PRD.md §10 릴리스 계획

## 맥락

플랫폼은 여러 마일스톤(콘텐츠 모델, 진도 추적, 복습, 실습 연동, 정적 사이트)을 거쳐 완성된다. Claude Code 에이전트가 이 작업의 상당 부분을 수행하는데, 에이전트 작업은 (1) 검증 없이 "끝났다"고 보고하거나, (2) 같은 실패를 무한히 반복하거나, (3) 명세 없이 범위를 넓히는 문제가 반복된다. 작업 흐름을 명시적으로 모델링하고 게이트와 반복 상한을 두는 구조가 필요하다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 자유 형식(에이전트가 알아서 계획·구현·검증) | 설정 비용 없음 | 검증 누락, 무한 반복, 범위 확장이 빈번. 재현·감사 불가 |
| B. 고정 파이프라인(계획→구현→테스트 1회) | 단순, 예측 가능 | 실패 시 재시도 구조가 없어 사람이 매번 개입 |
| C. 그래프(노드·게이트·루프 노드) + 상태 저장소 | 루프마다 종료 조건·상한, 게이트는 실행 근거로 판정, 상태가 파일로 남아 재개·감사 가능. 노드 추가로 확장 | 초기 설정 비용, 워크플로 실행 시 에이전트 비용 |

## 결정

C 를 택한다.
- 그래프 정의는 `harness/graph.md`, 상태는 `harness/roadmap.yaml`, 실행기는 `.claude/workflows/*.js`(Claude Code Workflow: 루프·분기는 스크립트가 결정적으로 제어), 노드 실행자는 `.claude/agents/*.md`.
- 루프 노드 3종: L1 implement→verify(max 3), L2 review→adversarial verify→fix(max 2), L3 acceptance 재분해(max 2). 바깥 루프 L0 는 마일스톤 단위이며 `maxMilestones` 와 토큰 예산으로 제한.
- 모든 게이트(verify, adversarial verify, acceptance)는 명령 실행·파일 확인을 근거로 구조화된 판정을 낸다.
- 훅(Stop 게이트, Bash 가드)은 워크플로 밖의 일상 작업에도 같은 규율을 적용한다.

## 결과

- 얻는 것: 마일스톤별 명세·보고서·커밋이 남는 재현 가능한 개발 이력, 반복 상한으로 인한 비용 상한, 사람 개입 지점(blocked)의 명확화.
- 잃는 것 / 리스크: 워크플로 1회 실행에 에이전트 10~30개가 뜬다(비용). 소규모 변경에는 과하므로 `/verify` 등 단독 경로를 유지한다. Workflow 중첩은 한 단계만 가능해 `milestone` 안에 루프가 인라인되어 있다(중복 코드).
- 후속 작업: P0-1 에서 pyproject.toml 이 생기면 check.sh 와 Stop 게이트가 실제로 동작하는지 확인. 첫 마일스톤 실행 후 반복 상한(3/2/2)을 조정.
