# 0020. 레슨 그림은 저장소의 스크립트로 생성한 SVG 다

- 상태: accepted
- 날짜: 2026-11-28
- 관련: docs/curriculum/CONTENT_MODEL.md 규칙 16, docs/curriculum/LESSON_TEMPLATE.md, GitHub #60

## 맥락

기초 단계 레슨에는 그림이 하나도 없었다. 좌표계, 팔의 작업 영역, 차동 구동의 회전 중심처럼 글과
수식만으로는 잡히지 않는 내용이 많다는 의견이 있었다(#60). 그림을 넣는 방식은 한 번 정하면
레슨 수십 개에 퍼지므로 되돌리기 비싸다. 제약은 다음과 같다.

- 콘텐츠는 CC BY 4.0 이고 외부 자료는 복제하지 않는다. 교재·논문의 그림을 가져올 수 없다.
- 한국어와 영어 두 판이 있다. 그림 안에 문장이 있으면 그림도 두 벌이 된다.
- 오프라인 정적 사이트와 서버 모드 웹이 같은 파일을 보여 준다.
- 본문의 숫자(예제 코드의 출력)와 그림이 어긋나면 그림이 틀린 정보가 된다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| 그리기 도구로 만든 이미지를 커밋 | 표현이 자유롭다 | 원본이 저장소 밖에 있어 고치기 어렵고, 본문 숫자와 어긋나도 알 수 없다 |
| matplotlib 으로 빌드할 때 생성 | 익숙한 도구 | 무거운 의존성, 버전·글꼴에 따라 출력이 달라져 재현 검사가 어렵다 |
| Mermaid 등 본문 안 다이어그램 | 파일이 없다 | 기하 그림(각도, 궤적)을 그릴 수 없고 웹·정적 사이트 양쪽에 렌더러가 필요하다 |
| **저장소의 작은 스크립트가 SVG 를 쓰고 결과를 커밋** | 의존성 없음, 결과가 결정적, 텍스트 diff 로 리뷰 | 그림마다 코드를 써야 하고 표현이 단순하다 |

## 결정

`scripts/figures/svgplot.py`(표준 라이브러리만 쓰는 작은 캔버스)와
`scripts/figures/make_figures.py`(그림 하나에 함수 하나)로 SVG 를 만들고, 결과를 레슨 옆
`figures/` 에 커밋한다.

- 그림은 레슨의 수식과 예제 코드와 같은 모델을 계산해 그린다(PID 응답 곡선은 레슨의 제어기를 그대로
  돌린 결과다).
- 라벨은 기호와 숫자만 쓴다. 한 파일이 모든 언어에 쓰이고, 설명은 레슨의 대체 텍스트에 언어별로 적는다.
- `make_figures.py --check` 가 커밋된 파일과 생성 결과가 같은지 확인하고 테스트가 이를 실행한다.
- `rc validate` 규칙 16 이 파일 존재, 대체 텍스트, 번역 간 일치, SVG 안의 스크립트·외부 참조 금지를
  검사한다. 웹은 레슨이 실제로 참조한 그림만 API 를 거쳐 내보낸다.

## 결과

- 얻는 것: 그림이 본문과 함께 리뷰되고, 고칠 때 코드 몇 줄만 바꾸면 되며, 저작권 문제가 없다.
- 잃는 것 / 감수하는 리스크: 사진이나 복잡한 삽화는 이 방식으로 만들 수 없다. 필요해지면 PNG 를
  허용하는 규칙 16 의 범위 안에서 출처와 라이선스를 적어 따로 추가한다. 플랫폼에 따라 부동소수점
  끝자리가 달라질 수 있어 좌표는 소수 둘째 자리로 반올림해 쓴다.
- 후속 작업: M4 이후 모듈의 그림은 레슨을 고칠 때 같은 방식으로 추가한다.
