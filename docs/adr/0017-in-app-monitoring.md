# 0017. 운영 지표를 앱 안에 저장하고 관리자 화면에서 본다

- 상태: accepted
- 날짜: 2026-11-22
- 관련: ADR 0016(공개 콘텐츠), docs/architecture/operations.md, docs/specs/P3-2.md,
  docs/operations/RUNBOOK.md §8.4

## 맥락

운영자가 서비스 상태를 보려면 지금은 두 가지뿐이다: `/metrics`(Prometheus 형식, 프로세스 메모리에만
있어 재시작하면 0 이 된다)와 컨테이너 로그. 이 배포는 단일 호스트이고 Prometheus·Grafana·로그
수집기가 없다. 그래서 "어제 저녁에 느렸나", "지난주에 몇 명이 왔나", "그 500 은 무슨 요청이었나"에
답할 곳이 없다. 방문 수는 아예 세지 않는다 — 브라우저는 웹 서버만 부르고 웹은 콘텐츠 응답을
캐시하므로 API 요청 수는 방문 수가 아니다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. Prometheus + Grafana(+Loki) 를 compose 에 추가 | 표준 도구, 알림까지 | 컨테이너 3~4개와 저장소·대시보드 관리가 생긴다. 방문 지표는 여전히 없다. 단일 호스트 배포에 과하다 |
| B. 외부 분석 서비스(GA, Plausible 호스팅) | 방문 지표가 바로 나온다 | 방문자 데이터가 제3자에게 간다. CSP 에 외부 스크립트를 열어야 한다. 서버 지표는 여전히 없다 |
| C. **앱이 집계해 자기 DB 에 저장하고 관리자 화면에서 보여 준다** | 추가 컨테이너 0, 데이터가 밖으로 나가지 않는다, 기존 관리자 권한·감사 로그를 그대로 쓴다 | 알림이 없다(보는 사람이 있어야 한다). 고해상도 시계열이 아니다. 직접 만든 코드를 유지해야 한다 |

C 를 택한다. A 를 막는 결정이 아니다 — `/metrics` 는 그대로 있고, 규모가 커지면 A 를 얹으면 된다.

## 결정

1. **API 요청**은 (시간 버킷, 라우트 템플릿, 메서드, 상태군)별로 집계한다: 건수, 소요 시간 합·최대,
   고정 경계 히스토그램(분위수 계산용). 요청마다 DB 에 쓰지 않는다 — 프로세스 안 버퍼에 모았다가
   주기적으로(기본 15초) 한 번에 더한다. 프로세스가 죽으면 마지막 주기만큼 잃는다(지표이지 장부가
   아니다).
2. **실패한 요청**(5xx)은 한 건씩 기록한다: 시각, 메서드, 라우트 템플릿, 경로, 상태, 소요 시간,
   요청 ID, 사용자 ID, 예외 종류와 메시지. **쿼리 문자열·헤더·본문은 기록하지 않는다**(토큰과 개인
   데이터가 거기 있다). 요청 ID 로 서버 로그의 전체 스택을 찾는다.
3. **방문**은 웹 서버가 문서 요청마다 API 에 알린다(브라우저 스크립트 없음, 쿠키 없음).
   저장하는 것은 (날짜, 경로, 언어, 사람/봇, 로그인 여부)별 건수와 유입 호스트별 건수다.
4. **순 방문자**는 `sha256(일별 솔트 ‖ IP ‖ User-Agent)` 의 앞 16자리로 센다. 솔트는
   `HMAC(RC_AUTH_SECRET, 날짜)` 라서 매일 바뀐다 — 같은 사람도 다음 날에는 다른 값이고, 값에서
   IP 를 되돌릴 수 없다. **IP 와 User-Agent 원문은 저장하지 않는다.** 그 대가로 주간·월간 순
   방문자는 셀 수 없다(일별 순 방문자와 그 합만 있다). 로그인 사용자 수는 감사 로그에서 따로 센다.
5. **수집 엔드포인트**(`POST /api/v1/telemetry/pageview`)는 `RC_API_TRUSTED_PROXIES` 안의 연결에서만
   받는다. 인터넷에서 직접 부를 수 없으므로 숫자를 부풀릴 수 없다.
6. **시스템 자원**은 저장하지 않고 요청 시점에 읽는다(`/proc`, `/sys`, 디스크, DB). 컨테이너 안에서
   읽으므로 메모리·부하·온도는 호스트 값이고 디스크는 데이터 볼륨이다. 읽을 수 없는 값은 `null`.
7. **보존**: 요청 집계 90일, 실패 기록 30일(최대 5,000건), 방문 집계 400일, 방문자 해시 35일.

## 결과

- 표 5개가 생긴다(`ops_*`, Alembic 0004). 서버 모드 전용이다.
- 개인 데이터 관점: 방문자 해시는 하루 동안만 같은 사람을 가리키는 가명 정보이고 35일 뒤 지워진다.
  실패 기록의 사용자 ID 는 30일 보존이다. 둘 다 계정 삭제 시 함께 지운다(사용자 ID).
- 이 지표는 **운영 판단용**이다. 과금·감사의 근거로 쓰지 않는다(재시작 시 최대 한 주기 유실,
  여러 워커가 같은 버킷을 더하는 것은 안전하지만 순서는 보장하지 않는다).
- 알림이 필요해지면 `/metrics` 를 Prometheus 로 긁고 Alertmanager 를 붙인다. 그때도 방문 지표와
  실패 기록은 이 결정대로 남는다.

## 개정 (2026-11-22): 날짜는 서비스 시간대 기준

방문·방문자·유입 집계의 `day` 는 처음에 UTC 날짜였다. 운영자가 보는 "오늘"이 오전 9시에 바뀌는
셈이라, 서비스 시간대(`RC_TIMEZONE`, 기본 `Asia/Seoul`)의 날짜로 바꿨다(Alembic 0005 는 열 설명만
바꾼다). 방문자 해시의 솔트도 그 날짜를 따른다. 요청 집계의 시간 버킷은 절대 시각 그대로다.
