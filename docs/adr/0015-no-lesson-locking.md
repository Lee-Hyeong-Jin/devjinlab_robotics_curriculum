# 0015. 레슨 잠금을 없애고 선수지식은 권장으로만 남긴다

- 상태: accepted
- 날짜: 2026-11-12
- 관련: docs/PRD.md FR-2(로드맵·선수지식 그래프), harness/roadmap.yaml P1-3,
  docs/architecture/frontend.md, docs/api/openapi.yaml

## 맥락

선수 레슨이 완료되지 않은 레슨은 `locked` 로 표시되고, 화면에서는 잠금 아이콘과 비활성 카드로
막혀 있었다(`rc roadmap` 의 `[-]`, 정적 사이트의 `▨`, web 의 🔒·링크 없는 카드). 다만 **코어는
한 번도 막지 않았다** — `rc start/log/done` 과 API 의 쓰기 엔드포인트는 경고만 내고 그대로
진행했다. 즉 잠금은 처음부터 표시뿐이었고, 쓰기는 늘 열려 있었다.

사용자(저장소 소유자, 2026-11-12, "과정에 잠김 다 풀어줘")는 이 표시가 실제보다 더 엄격해
보이고 쓸모가 없다고 판단했다. 혼자 학습하는 사람이 순서를 건너뛰는 것은 막아야 할 실수가 아니다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 현행 유지 | 변경 0 | 막히지 않는데 막힌 것처럼 보인다. 잠긴 카드는 링크조차 없어 읽을 수도 없다 |
| B. 잠금 표시만 없애고 `locked` 데이터는 유지 | API 계약 무변경 | "항상 false 인 필드"가 남아 다음 사람이 다시 UI 를 만들 여지가 있다 |
| C. 잠금 개념을 없애고 미완료 선수지식을 **정보**로 제공 | 모델이 실제 동작과 일치한다. 선수지식 정보는 그대로 쓸 수 있다 | API 필드 1개가 deprecated 가 되고, 코어 자료구조·테스트가 바뀐다 |

C 를 택한다. B 는 거짓말하는 필드를 남긴다.

## 결정

**아무 것도 잠기지 않는다.** 선수지식은 "권장 순서"에 대한 조언이고, 모든 레슨은 언제든 시작·기록·
완료할 수 있다(전에도 그랬다).

### 코어

- `LessonSummary.locked: bool` → `missing_prerequisites: tuple[str, ...]`, 그리고 편의 속성
  `recommended`(= 미완료 선수지식이 없음).
- `next_lessons()` 는 **걸러내지 않는다**. 정렬만 한다: 진행 중 → 선수지식 완료 → 나머지, 각 묶음
  안에서는 교수 순서(stable sort). 전에는 선수 미완료 레슨이 목록에서 사라졌다.
- `rc start/log/done` 의 경고(`cli.warn_prereq`)는 안내(`cli.note_prereq`)로 문구를 바꿨다.
  차단은 전에도 없었다.
- `rc roadmap` 의 `[-]` 표식과 `rc status`·모듈 리포트의 "잠김" 상태 라벨을 없앴다. 상태는
  `not_started | in_progress | done` 셋뿐이다.
- `done()` 이 돌려주는 목록은 "이 완료로 **추천 순서에 들어온** 레슨"이다(해금이 아니다).

### API (하위 호환)

- `LessonState.locked` 는 **남기되 항상 false** 이고 `deprecated: true` 다. 기존 클라이언트가
  계속 파싱하도록 두고, 대신 `missing_prerequisites: string[]` 를 제공한다.
- `LockState` 열거에 `locked` 값은 남아 있지만 서버는 더 이상 내보내지 않는다. 클라이언트의
  exhaustive match 가 깨지지 않게 하려는 것이다.
- `DoneResult.unlocked_lesson_ids` 는 이름을 유지하고 설명만 고쳤다(필드 이름을 바꾸면 계약
  파손이고, 의미는 "이제 추천 순서에 들어온 레슨"으로 충분히 가깝다).

### 정적 사이트

`▨ 잠김` 배지를 없앴다. 선수 레슨이 미완료인 레슨에는 경고(`!!! warning`) 대신 안내
(`!!! note "권장 선수 레슨"`)를 두고 해당 레슨 id 를 적는다. 선수 레슨은 링크와 완료 여부만 보인다.

### web

`LockState` 에서 `'locked'` 를 **타입 수준에서 제거**하고, API 경계의 `normalizeState()` 가
옛 서버의 `locked` 를 `available` 로 바꾼다. 그래서 어떤 화면도 실수로 잠금을 다시 그릴 수 없다
(타입 검사가 막는다). 잠금 아이콘·비활성 카드·불투명 처리가 사라지고 모든 레슨·모듈 링크가
활성이다. 레슨 화면에는 "권장 선수 레슨" 카드가 생겨 미완료 선수 레슨을 링크로 보여 준다
(`GET /progress/status` 가 이미 담고 있어 추가 요청이 없다).

## 결과

- 얻는 것: 모델이 실제 동작과 일치한다. 순서를 건너뛰는 사람이 레슨을 **읽을 수** 있다
  (전에는 잠긴 카드에 링크가 없어 열 수조차 없었다). 선수지식 정보는 조언으로 그대로 쓰인다.
- 감수하는 것: `locked` 가 영원히 false 인 deprecated 필드로 남는다(다음 메이저에서 제거 후보).
  추천 순서를 무시하고 진행하는 학습자를 아무도 막지 않는다 — 이것이 의도다.
- PRD 는 고치지 않았다(FR-2 는 "선수지식 그래프"를 요구하고 그래프는 그대로 있다. 잠금은 PRD 가
  요구한 적이 없다).
- 후속: 다음 메이저에서 `LessonState.locked` 와 `LockState` 의 `locked` 값 제거.
