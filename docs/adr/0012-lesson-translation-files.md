# 0012. 레슨 번역 파일: `<lesson>.<lang>.md` 형제 파일

- 상태: accepted
- 날짜: 2026-11-11
- 관련: docs/PRD.md FR-9(i18n), harness/roadmap.yaml P2-6; docs/adr/0011-i18n-message-catalog.md
  (UI 문자열); docs/curriculum/CONTENT_MODEL.md

## 맥락

ADR 0011 로 UI 문자열은 번역된다. 남은 것은 **콘텐츠**다: 레슨 제목·요약·학습 목표·본문을
다른 언어로 제공하되, 커리큘럼 구조(선수지식, 난이도, 예상 시간, 활동, 자료)는 언어와 무관하게
하나로 유지해야 한다. 제약: 저자는 Git 으로 Markdown 을 편집하고, `rc validate` 가 오류를
잡아야 하며, 번역이 없는 레슨은 원문(한국어)으로 폴백해야 한다. 번역 분량은 레슨 31개 × 언어 수
이며 당분간 영어 일부만 존재한다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 형제 파일 `<lesson>.<lang>.md` | 원문 옆에 있어 저자가 번역 유무·최신성을 바로 본다. 로더가 이미 같은 디렉터리를 글롭한다. 파일 이름만으로 언어가 결정된다. | 모듈 디렉터리에 파일이 언어 수만큼 늘어난다. `module.yaml` 의 `lessons` 목록과 섞이지 않게 접미사 판별이 필요하다. |
| B. 모듈 안 `locales/<lang>/<lesson>.md` | 모듈 디렉터리가 깔끔하고 언어별 디렉터리 복사가 쉽다. | 같은 레슨의 원문과 번역이 멀어진다. 디렉터리 구조가 모듈마다 중복된다. 로더가 하위 디렉터리를 새로 스캔해야 한다. |
| C. 한 파일 안에 언어별 섹션 | 파일 수가 늘지 않는다. | front matter 와 본문이 언어별로 중첩돼 스키마가 복잡해지고, 번역 diff 가 원문 diff 와 섞인다. 대형 번역에 부적합. |
| D. 번역 플랫폼(PO/XLIFF)으로 본문까지 관리 | 번역 도구 생태계 | Markdown 본문(수식·코드 블록)을 메시지 단위로 쪼개면 손상 위험이 크고 저자 흐름과 맞지 않다. |

## 결정

A(형제 파일)를 택한다.

- 파일 이름: `<lesson>.<lang>.md`. `<lang>` 은 지원 언어 목록(`robotics_curriculum.i18n.LANGS`)에
  있어야 하고, 원문 언어(`ko`) 접미사는 금지한다(원문은 접미사 없는 파일이다).
- 번역 front matter 는 **텍스트만** 담는다: `title`, `summary`(필수), `objectives`, `tags`(선택,
  생략 시 원문 상속), 확인용 `id`·`lang`(선택, 값이 다르면 오류). 구조 필드(`prerequisites`,
  `difficulty`, `estimated_minutes`, `activities`, `resources`)는 번역 파일에 쓸 수 없다
  (`extra="forbid"`). 따라서 번역이 선수지식 그래프나 활동을 바꿀 수 없다.
- 로더는 접미사 있는 파일을 레슨 목록에서 제외하고 해당 레슨의 `translations[lang]` 로 붙인다.
  대응 원문이 없는 번역, 지원하지 않는 언어, 빈 본문은 `rc validate` 오류다.
- 조회는 `Lesson.localized(lang)` 하나로 한다: 번역이 있으면 그 텍스트, 없으면 원문을 돌려주고
  `translated`·`lang` 으로 무엇이 쓰였는지 알린다. API 는 `Accept-Language`, 정적 사이트는
  `rc site build --lang` 으로 언어를 고른다. 응답에는 `lang` 과 `available_languages` 를 담아
  클라이언트가 폴백 여부를 알 수 있게 한다.
- 본문의 "이 단계 공부법" 절은 번역본에서 그 언어의 제목으로 쓴다. 추출은 요청 언어의 카탈로그
  제목을 먼저 찾고 없으면 한국어 제목으로 폴백한다(`content.sections.extract_study_guide`).

## 결과

- 얻는 것: 번역 추가가 파일 하나 추가로 끝나고, 구조는 단일 출처로 남는다. 번역 누락이 오류가
  아니라 폴백이므로 점진적 번역이 가능하다.
- 잃는 것 / 감수하는 리스크: 원문이 바뀌어도 번역이 자동으로 "낡음" 표시되지 않는다(해시나
  `source_rev` 필드는 후속 과제). 모듈 디렉터리의 파일 수가 언어 수에 비례해 늘어난다.
- 후속 작업: 번역 최신성 추적(원문 개정 표시), 번역 진행률 리포트, 웹 프론트엔드의 언어 전환
  UI(P2-4). 실제 번역 콘텐츠 작성은 콘텐츠 저자 세션의 일이며, 이 결정은 그 그릇만 정한다.
