# 0011. 다국어 메시지: YAML 카탈로그 (gettext 미채택)

- 상태: accepted
- 날짜: 2026-11-11
- 관련: docs/PRD.md FR-9(i18n), §7 비기능(접근성·현지화); harness/roadmap.yaml P2-6;
  .claude/rules/engineering.md(의존성 최소화, Apache-2.0 호환)

## 맥락

사용자에게 보이는 문자열이 코드에 한국어로 박혀 있다(CLI 출력, 정적 사이트 UI 라벨, API 오류
제목). 오픈소스 공개와 영어 사용자 지원을 위해 번역 가능한 구조가 필요하다(P2-6, QA 리뷰
QA-16). 제약: 오프라인 동작, 런타임 의존성 최소, 빌드 단계 추가 없음, 외부 기여자가 번역 파일을
PR 로 고칠 수 있어야 하고, 번역이 비어 있어도 프로그램이 멈추지 않아야 한다. 레슨 본문 등
커리큘럼 콘텐츠는 번역 대상이 아니다(콘텐츠 자체가 한국어 교육 자료이며 파일로 관리된다).

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. YAML 카탈로그 + 자체 `Translator` | 의존성 0(pyyaml 은 이미 콘텐츠 로더가 사용), 빌드 단계 없음, 외부 기여자가 읽고 고치기 쉬움, 키 누락 폴백·테스트가 단순, 사전 자체를 테스트에서 주입 가능 | 복수형·성별 변화 규칙 없음, 번역 도구(Weblate 등) 연동은 변환 필요 |
| B. gettext (`.po`/`.mo`, 표준 라이브러리 `gettext`) | 표준이며 번역 도구 생태계가 넓음, 복수형 규칙 내장 | `.mo` 컴파일(빌드 단계)과 바이너리 산출물을 저장소에 둬야 하고, `msgfmt`(gettext 도구)가 개발·CI 환경에 필요, 키가 영문 원문이라 한국어 원본과 맞물리면 혼란 |
| C. Babel + gettext | 추출·병합 도구 제공 | 런타임 의존성 추가(Babel), B 의 단점 유지 |

## 결정

A(YAML 카탈로그)를 택한다.

- `src/robotics_curriculum/i18n/locales/<lang>.yaml` 한 파일이 한 언어다. 가독성을 위해
  중첩해 쓰고 로드 시 점으로 구분된 키(`cli.timer.none`)로 평탄화한다. 값은 `str.format`
  템플릿이며 **이름 있는 인자만** 쓴다.
- `Translator(lang)` 의 조회는 예외를 던지지 않는다: 선택 언어에 키가 없으면 원본 언어(ko)로,
  그것도 없으면 키 문자열 자체로 폴백하고 경고를 로그에 남긴다. 반쪽 번역이 명령을 깨뜨리지
  않는다. 포맷 인자가 맞지 않아도 템플릿 원문을 돌려준다.
- 로드는 `yaml.safe_load` 로만 하고 파일 오류는 경고 후 빈 카탈로그로 처리한다. 로케일 파일은
  외부 기여 대상이므로 **신뢰하지 않는 입력**으로 취급한다: 사이트 렌더러는 번역 결과도
  `md_text()`/`html.escape` 를 거친다.
- 언어 선택 우선순위: `--lang` > `RC_LANG` > `Accept-Language`(API 요청 단위) > `ko`.
  태그는 `en-US`, `EN`, `en_us` 모두 `en` 으로 정규화하고, 지원하지 않는 값은 무시한다.
- 지원 언어는 `ko`(원본), `en`. 새 언어는 `locales/<lang>.yaml` 추가와 `Lang` 리터럴 확장만
  필요하다.
- 1차 범위: CLI 공통 메시지, 퀴즈·복습 세션 출력, 자료·로드맵 라벨, API problem 제목, 정적
  사이트 UI 라벨. **콘텐츠 본문·레슨 메타데이터는 범위 밖**이다.

## 결과

- 얻는 것: 의존성·빌드 단계 추가 없이 번역 가능. 번역 누락이 런타임 오류가 되지 않는다.
  테스트에서 `translator("en")` 하나로 전체 출력 언어를 바꿀 수 있다.
- 잃는 것 / 감수하는 리스크: 복수형 규칙이 없다(영어 메시지는 `card(s)` 처럼 중립 표기로 쓴다).
  번역 플랫폼 연동이 필요해지면 YAML↔PO 변환이나 gettext 재검토가 필요하다. 키 누락은
  테스트(ko/en 키 집합 동일성)로 막는다.
- 후속 작업: 웹 프론트엔드(P2-4)는 같은 카탈로그를 API 또는 빌드 시 JSON 으로 받아 쓴다.
  날짜·숫자 현지화와 복수형이 필요해지면 그때 별도 ADR 로 다룬다.
