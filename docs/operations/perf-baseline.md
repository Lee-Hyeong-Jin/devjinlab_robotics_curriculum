# API 성능 기준선 (읽기 엔드포인트)

PRD §7("성능 / 서버")의 목표는 **읽기 p95 ≤ 300 ms**, 쓰기 p95 ≤ 1 s, 동시 사용자 500명·레슨
1,000개 기준이다. 이 문서는 그 중 **읽기 p95** 를 재는 기준선과, 실제로 측정한 값을 기록한다.

측정 도구는 `scripts/perf/api_load.py` — 의존성을 더하지 않고 asyncio + 패키지가 이미 쓰는
`httpx` 로 돌린다. 백분위는 **nearest-rank** 라서 보고된 값은 실제로 일어난 요청 하나의 시간이다.

```bash
# local 모드(자격 증명 없이)
RC_AUTH_MODE=local RC_DATA_DIR=$(mktemp -d) uv run rc api serve --port 8098 &
uv run python scripts/perf/api_load.py --base-url http://127.0.0.1:8098

# server 모드(read:progress 스코프 PAT 필요)
uv run python scripts/perf/api_load.py --base-url http://127.0.0.1:8099 --token rcp_...

# 한 엔드포인트만, 더 오래
uv run python scripts/perf/api_load.py --base-url ... --only lesson --duration 30
```

`--format json` 은 같은 수치를 기계가 읽는 형태로 낸다. 종료 코드는 요청이 **전부** 실패했을 때만
1 이고, 목표 초과는 stderr 경고로만 알린다(회귀를 조사하는 동안 루프에서 계속 쓸 수 있도록).

## 2026-11-12 기준선

측정 환경: 개발용 노트북(Linux x86_64, Python 3.12.3), SQLite 저장소, 레슨 50개,
커리큘럼 1개 코스. API 와 부하 생성기가 **같은 기계**에서 돌고, 그 기계에서 다른 작업(다른 세션의
빌드·테스트)이 동시에 돌고 있었다. 즉 아래 값은 낙관이 아니라 **보수적인 쪽**이다. 동시 16,
엔드포인트당 2초, 워밍업 5요청.

## 읽기

- **목표는 충족한다.** 모든 읽기 엔드포인트가 p95 300 ms 아래이고, 가장 느린 것(`progress.status`,
  158 ms)도 목표의 절반 정도다. 실패 요청은 0건이다.
- **인증 비용은 작다.** server 모드가 local 모드보다 p95 기준 10–40 ms 느리다. 요청마다 세션
  또는 토큰 조회 1회가 더 붙는 설계대로이고(ADR 0010 "감수하는 것"), 목표 대비 여유가 크다.
- **느린 쪽은 진행도 집계다.** `progress.status`·`progress.next`·`progress.lessons`·
  `reports.weekly` 는 콘텐츠 조회보다 2배 정도 느리다. 콘텐츠는 메모리 색인이고 이들은 요청마다
  저장소를 읽어 집계하기 때문이다. 캐시를 넣을 자리가 생기면 여기가 먼저다.
- **p99 와 max 는 신뢰하지 말 것.** 1초를 넘는 꼬리가 몇 개 보이는데, 같은 기계에서 다른 빌드가
  동시에 돌던 탓이다. 전용 기계가 아니면 p99 비교는 의미가 없다. 비교는 p50·p95 로만 한다.

## 아직 측정하지 않은 것 (정직하게)

- **쓰기 p95(목표 1 s)**: 이 도구는 읽기만 센다. 쓰기는 진행도 행을 만들어 상태를 바꾸므로
  측정마다 DB 를 초기화해야 하고, 그 설계를 아직 하지 않았다.
- **동시 사용자 500명·레슨 1,000개**: 위 수치는 동시 16·레슨 50 이다. PRD 의 규모에서 재려면
  콘텐츠 생성기와 사용자별 세션 풀이 필요하다.
- **PostgreSQL 저장소**: 위는 SQLite 다. compose 스택(ADR 0007)에서 다시 재야 한다.
- **전용 기계 / CI**: 위 수치는 공유된 개발 기계의 것이다. 기준선으로 비교하려면 같은 방식으로
  기록한 값끼리만 비교한다.
- **웹 페이지 LCP 2.5 s(PRD §7)**: Lighthouse 가 필요하다 —
  [lighthouse.md](lighthouse.md) 를 보라.

## 다시 잴 때

같은 명령·같은 `--concurrency`·같은 `--duration` 으로 돌리고, 결과를 이 문서에 **새 절로** 덧붙인다
(위 표를 덮어쓰지 않는다). 환경(기계, 저장소, 레슨 수, 동시 부하)을 함께 적는다. 환경이 다르면
수치는 비교 대상이 아니다.
