## 처음 실행에서 걸린 것 두 가지 (모두 수정했다)

1. **`check.sh` 의 web lint 실패** — 이 워크트리의 `web/node_modules` 가 프론트엔드의 Next 16
   업그레이드 이전 상태였다(`eslint-config-next/core-web-vitals` 를 찾지 못함). `npm ci` 로
   맞춘 뒤 통과. 코드 문제가 아니라 환경 문제였고, CI 는 매번 `npm ci` 를 하므로 영향 없다.
2. **복구 리허설 실패** — SRV-06 으로 compose 가 비밀값을 필수로 요구하게 되고 api 가 server
   모드가 되면서 `scripts/ops/restore_drill.sh` 가 깨져 있었다(`RC_DB_PASSWORD` 미설정으로
   compose 기동 실패, 그리고 비인증 API 호출). 스크립트가 smoke.sh 처럼 일회용 비밀값을 만들고,
   드릴 계정을 만들어 세션 쿠키와 `X-CSRF-Token` 으로 호출하도록 고쳤다. 같은 이유로 CI 의
   `restore-drill` 잡도 이 수정 전에는 실패했을 것이다.

## 버전 표기

`pyproject.toml` 하나만 올리면 되도록 정리했다. `__version__` 은 설치된 배포판에서 읽고,
`tests/test_version.py` 가 `pyproject.toml` 과 어긋나면 실패시킨다. 웹은 `web/package.json` 과
`package-lock.json` 을 같은 값으로 맞췄다.
