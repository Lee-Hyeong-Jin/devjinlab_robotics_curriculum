## 1. 개요

이 플랫폼은 **로보틱스 전문가 코스를 위한 전용 커리큘럼 플랫폼**이다. 범용 학습 플랫폼이 아니라, 로보틱스 전문가가 되기까지의 단계별 코스 하나("로보틱스 전문가 코스", 기초 → 중급 → 고급)를 담는다.

목적은 **그 코스의 커리큘럼, 개인 학습 진행도, 단계별 학습 방법과 자료를 보기 편하게 하는 것**이다. 학습자는 무엇을 어떤 순서로 배울지(커리큘럼), 지금 어디까지 왔는지(진행도), 각 단계에서 무엇을 어떻게 공부할지(학습 방법·자료)를 한 곳에서 본다.

시뮬레이터 연동 같은 복잡한 기능은 범위에 넣지 않는다(3.2절). 콘텐츠는 저장소 안의 Markdown/YAML 파일로 관리하여 Git으로 버전 관리한다.

이 프로젝트는 **오픈소스로 공개하고 실제 엔터프라이즈급 품질로 개발한다**(사용자 결정, 2026-11-11). 개인 학습자가 로컬에서 쓰는 것은 물론, 교육기관·스터디 그룹·기업 교육팀이 자체 호스팅해 여러 학습자를 운영할 수 있어야 한다. 따라서 두 가지 실행 모드를 둔다.

- **로컬 모드**(Phase 1, 현재): 코어 라이브러리 + Python CLI `rc` + 정적 사이트. 단일 사용자, SQLite, 네트워크 불필요.
- **서버 모드**(Phase 2 이후): 같은 코어 라이브러리 위에 API 서버, 웹 프론트엔드, PostgreSQL, 인증·권한을 얹은 멀티유저 웹 플랫폼. Docker Compose로 자체 호스팅.

두 모드는 콘텐츠 모델과 코어 로직을 공유하며, 로컬 모드는 서버 모드가 생긴 뒤에도 계속 지원한다.

## 2. 배경 및 문제 정의

로보틱스는 수학(선형대수, 미적분), 물리(동역학), 제어, 소프트웨어(ROS 2, 시뮬레이션), 하드웨어(센서, 액추에이터)가 얽혀 있어 독학 시 다음 문제가 반복된다.

1. **순서 혼란**: 무엇을 먼저 배워야 하는지(선수지식) 명확하지 않다.
2. **분산된 자료**: 책, 논문, 강의, 블로그가 흩어져 있고 메모(`research_notes/`)와 학습 내용이 연결되지 않는다.
3. **학습 방법 불명확**: 각 단계에서 어떤 교재의 몇 장을 읽고, 어떤 연습문제를 풀고, 어떤 강의를 볼지 정리돼 있지 않다.
4. **망각**: 복습 체계가 없어 몇 주 뒤 다시 처음부터 본다.
5. **진도 불투명**: 어디까지 했고 얼마나 남았는지, 주간 단위로 무엇을 했는지 알 수 없다.

## 3. 목표와 비목표

### 3.1 목표

- G1. 선수지식 그래프가 있는 **구조화된 커리큘럼**을 보기 편하게 제공한다.
- G2. 레슨 단위로 **진행도·시간·이해도**를 기록하고 대시보드로 보여준다.
- G3. 레슨·모듈마다 **단계별 학습 방법과 자료**(무엇을 어떤 순서로 어떻게 공부할지)를 정리해 보여준다.
- G4. 퀴즈와 **간격 반복(spaced repetition)** 으로 복습을 자동화한다.
- G5. 학습 기록으로 **주간/모듈 리포트**를 자동 생성해 `reports/`에 남긴다.

### 3.2 비목표 (이번 범위 밖)

- **Webots 등 시뮬레이터 연동, 실습 자동 실행·판정** (사용자 결정, 2026-11-11). 시뮬레이터는 학습 자료로 소개만 한다.
- 결제·구독·과금, 수료증 발급 같은 상용 LMS의 상거래 기능 (멀티유저·인증·권한 자체는 Phase 2 범위에 포함)
- 실제 로봇 하드웨어 제어
- 콘텐츠 마켓플레이스 또는 외부 강의 판매
- 모바일 네이티브 앱 (반응형 웹까지만)

## 4. 대상 사용자

| 페르소나 | 설명 | 핵심 니즈 |
|---|---|---|
| **P1. 학습자 (learner)** | 로보틱스 전문가 수준까지 기초 → 중급 → 고급 단계를 순서대로 공부하는 개인. 첫 사용자는 저장소 소유자 본인. 서버 모드에서는 기관·스터디 그룹의 구성원. | 코스 전체 지도와 현재 위치 파악, 단계별 학습 방법·자료 열람, 진행도·복습 관리, 자기 데이터 내보내기 |
| **P2. 콘텐츠 작성자 (author)** | 코스의 모듈·레슨·공부법·자료를 추가·수정하는 사람. 로컬 모드에서는 P1과 동일 인물, 오픈소스에서는 외부 기여자 포함. | Markdown/YAML로 쉽게 작성, 검증 도구, 미리보기, Git 기반 기여 워크플로 |
| **P3. 관리자 (admin)** | 서버 모드 인스턴스를 운영하는 교육기관·스터디 그룹·기업 교육팀 담당자. | 설치·업그레이드 용이성, 사용자·역할 관리, 백업·복구, 감사 로그, 모니터링 |
| **P4. 운영 기여자 (후순위)** | 오픈소스 프로젝트에 코드·번역·플러그인으로 기여하는 개발자. | 명확한 기여 가이드, 테스트·CI, 안정적인 공개 API |

로컬 모드는 P1/P2가 동일 인물인 **단일 사용자** 환경이다. 서버 모드는 역할 기반 권한(learner/author/admin)으로 다수 사용자를 분리한다. 코스는 하나뿐이므로 코스 선택·탐색 UI는 만들지 않되, 기관이 코스를 포크해 자체 버전을 운영할 수 있어야 한다.

## 5. 핵심 사용자 시나리오

1. **첫 방문**: 정적 사이트의 코스 로드맵 페이지에서 기초/중급/고급 세 단계와 모듈별 선수지식 그래프, 예상 소요 시간, 현재 위치를 보고, `rc next`가 시작 레슨을 추천한다.
2. **학습 방법 확인**: `rc show <lesson>` 또는 레슨 페이지에서 본문의 "이 단계 공부법" 절(예: 교재 3장 읽기 → 강의 2편 → 연습문제 5개 → 퀴즈)과 프런트매터 `resources[]`의 자료 목록(제목, 링크, 종류, 범위 메모)을 본다. `rc resources --module <id>`로 모듈 전체 자료를 한눈에 본다.
3. **레슨 학습**: 공부법 절을 따라 진행하며 활동(reading/quiz/exercise)을 `rc done`으로 체크하고, 핵심 개념 체크 퀴즈(`rc quiz <lesson>`)를 푼 뒤 이해도(1~5)와 메모를 남긴다.
4. **복습**: `rc review`가 오늘 복습할 카드 N개를 터미널에 띄우고, 응답에 따라 다음 복습 일정이 조정된다.
5. **주간 리포트**: 매주 학습 시간, 완료 레슨, 퀴즈 정답률, 막힌 지점을 Markdown 리포트로 생성해 `reports/YYYY-WW.md`에 저장한다.
6. **콘텐츠 작성**: 작성자가 `curriculum/robotics-expert/<module>/`에 레슨 파일(프런트매터 `resources[]` + 본문 "이 단계 공부법" 절)을 추가하고 `module.yaml`의 `lessons`에 등록하면, `rc validate`가 스키마·선수지식 참조·순환 의존·목록 누락을 검사하고 `rc build`로 정적 사이트에 반영된다. 오픈소스 기여자는 같은 변경을 PR로 보내고 CI가 검증한다.
7. **자체 호스팅 (Phase 2)**: 스터디 그룹 관리자가 `deploy/`의 Docker Compose로 인스턴스를 올리고, OIDC 제공자를 설정한 뒤 학습자를 초대한다. 학습자는 각자 로그인해 자기 진도만 보고, 관리자는 그룹 집계와 감사 로그, 백업 상태를 본다. 학습자는 언제든 자기 데이터를 JSON으로 내보내거나 계정을 삭제할 수 있다.

## 6. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = v1.0, **P2** = 이후.

### FR-1. 커리큘럼 콘텐츠 모델 및 관리 (P0)

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-1.1 | 콘텐츠 계층은 `Course > Module > Lesson > Activity`로 구성한다. 코스는 "로보틱스 전문가 코스"(id: `robotics-expert`) 하나이며, 단계(기초/중급/고급)는 별도 디렉터리가 아니라 `module.yaml`의 `level` 필드다. | 디렉터리 구조 `curriculum/robotics-expert/<module>/<lesson>.md`, 코스·모듈 메타는 `course.yaml`, `module.yaml`. 확정 스키마는 `docs/curriculum/CONTENT_MODEL.md`. |
| FR-1.2 | 레슨은 YAML 프런트매터가 있는 Markdown 파일이다. | 필수 필드: `id`, `title`, `summary`, `objectives[]`, `difficulty`, `estimated_minutes`. 선택: `prerequisites[]`, `tags[]`, `activities[]`, `resources[]`(FR-6.1). 모르는 키는 에러. |
| FR-1.3 | Activity 종류는 `reading`, `quiz`, `exercise`(연습문제)다. 레슨 프런트매터 `activities[]`에 둔다. | 각 종류별 렌더링. `external` 등 추가 종류는 필요해질 때 확장. |
| FR-1.4 | 콘텐츠 검증 CLI `rc validate`를 제공한다. | 스키마 위반, 목록(`modules`/`lessons`) 누락, ID 중복, 존재하지 않는 선수지식, 순환 의존을 감지하면 종료 코드 1을 반환한다. |
| FR-1.5 | 정적 사이트가 수식(LaTeX)과 코드 블록, 이미지, 임베드 영상을 렌더링한다. | KaTeX/MathJax 수식, Python/C++ 하이라이트가 깨지지 않는다. |

### FR-2. 학습 로드맵 및 선수지식 그래프 (P0)

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-2.1 | 코스 전체를 단계(기초/중급/고급) → 모듈 → 레슨의 선수지식 방향 그래프로 시각화한다(정적 사이트에 Mermaid 또는 Graphviz로 렌더링). | 완료/진행 중/잠김 상태가 색으로 구분되고 현재 단계가 강조되며, `rc build` 시 진도 DB를 반영한다. |
| FR-2.2 | 선수지식이 미완료인 레슨은 "잠김"으로 표시하되, 강제로 열 수 있다. | 강제 열기 시 경고 표시. |
| FR-2.3 | `rc next`가 현재 상태에서 "다음에 할 레슨"을 추천한다. | 선수지식 충족 + 미완료 레슨 중 코스 순서(단계 → 모듈 → 레슨)상 가장 앞선 것. |

### FR-3. 학습 진행도 추적 (P0)

용어: 사용자 문서·UI에서는 **"진행도"**(사용자 표현)를 정식 용어로 쓴다. "진도"는 같은 뜻의 짧은 표기로 CLI 출력·코드 식별자(`progress`, `.rc/progress.db`)·기존 문서에서 허용한다.

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-3.1 | `rc done <activity>` 등으로 Activity 상태(`not_started`, `in_progress`, `done`)를 기록한다. | SQLite에 즉시 저장되고 `rc status`로 확인된다. |
| FR-3.2 | 레슨 완료 시 이해도(1~5)와 자유 메모를 입력받는다. | 둘 다 선택 입력. |
| FR-3.3 | `rc start`/`rc stop` 타이머로 레슨별 누적 시간을 기록한다. | 수동 시간 입력(`rc log 45m`)도 가능. |
| FR-3.4 | 대시보드: 단계별·모듈별 진도율, 코스 전체 진도율, 주간 학습 시간, 연속 학습일(streak), 오늘 복습 수, 읽는 중인 자료. | `rc status`와 정적 사이트 첫 페이지 양쪽에 표시. |

### FR-4. 학습 보조: 퀴즈·간격 반복·노트 (P0/P1)

| ID | 우선순위 | 요구사항 | 수용 기준 |
|---|---|---|---|
| FR-4.1 | P0 | 레슨 안에 객관식·단답·O/X 퀴즈를 Markdown으로 정의한다. | 즉시 채점 및 해설 표시. |
| FR-4.2 | P0 | 틀린 퀴즈와 작성자가 지정한 핵심 개념은 자동으로 플래시카드가 된다. | 카드에 원본 레슨 링크 포함. |
| FR-4.3 | P0 | 간격 반복 알고리즘 **SM-2**로 복습 일정을 계산한다(`rc review`). FSRS는 Phase 2 이후 검토. | 응답(again/hard/good/easy)에 따라 다음 일정이 변하며, 계산은 단위 테스트로 검증. |

| FR-4.5 | P2 | 레슨 본문에서 텍스트를 선택해 하이라이트·주석을 남긴다(웹 앱 필요). | 하이라이트가 노트에 모인다. |

### FR-6. 학습 자료 및 단계별 학습 방법 (P0)

원칙은 "단순하게"다. 학습 방법은 구조화 데이터가 아니라 레슨 본문의 한 절로 쓰고, 자료는 레슨 프런트매터의 목록으로 둔다.

| ID | 우선순위 | 요구사항 | 수용 기준 |
|---|---|---|---|
| FR-6.1 | P0 | 레슨 프런트매터 `resources[]`에 학습 자료를 적는다. 각 항목은 `title`(필수), `url`, `kind`(`book`/`course`/`video`/`article`/`other`), `note`(범위·메모, 예: `Ch. 3`). | `rc validate`가 스키마를 검사하고, 레슨 페이지에 자료 목록이 렌더링된다. |

| FR-6.6 | P2 | Phase 2 제안: 자료 읽기 상태(미독/읽는 중/완료)와 `rc read`, 구조화된 학습 단계(`study_steps[]`)의 진도 추적, 자료 대안 병기, 코스 공용 자료 카탈로그. Phase 1 사용 경험으로 필요성이 확인될 때만 도입. | — |

## 8. 개념 데이터 모델

```
Course (robotics-expert, 1개; course.yaml: id, title, summary, tags, modules[] 순서)
 └──< Module (module.yaml: id, title, summary, level: 기초|중급|고급, lessons[] 순서)
       └──< Lesson (<lesson>.md 프런트매터: id, title, summary, objectives[], difficulty, estimated_minutes,
                    prerequisites[] (레슨 ID, DAG), tags[], activities[], resources[]; 본문에 "## 이 단계 공부법" 절)
              ├──< Activity (id, kind: reading|quiz|exercise, title, estimated_minutes)   ← 프런트매터 내장
              └──< Resource (title, url?, kind?: book|course|video|article|other, note?)   ← 프런트매터 내장

Progress   (user_id, lesson_id 또는 activity_id, status, understanding 1-5, note, updated_at)
Session    (user_id, lesson_id, started_at, ended_at, minutes)
Card       (id, lesson_id, front, back, source: quiz|concept)
Review     (card_id, reviewed_at, rating, next_due, interval, ease)
Note       (lesson_id, path, updated_at)   ← research_notes/ 파일을 색인
Report     (kind: weekly|module, period, path)

User       (id, email, password_hash: Argon2id | null, oidc_issuer+subject | null, role: learner|author|admin,
            created_at, deleted_at)                                   ← 서버 모드(Phase 2). 로컬 모드는 고정 user_id 1개
AuditLog   (id, actor_user_id, action, target, at, ip)                 ← 서버 모드, 관리 행위·인증 이벤트 기록
```

- 확정 스키마와 검증 규칙은 `docs/curriculum/CONTENT_MODEL.md`를 따른다. 자료 읽기 상태(ReadState)와 구조화 학습 단계(StudyStep)는 Phase 2 제안(FR-6.6)이라 모델에 넣지 않는다.
- 진도 데이터는 레슨 프런트매터의 `id` 문자열로 저장되므로(콘텐츠 테이블 FK 없음) 레슨 ID는 `curriculum/` 전체에서 유일해야 하고, 학습 기록이 있는 레슨의 ID는 바꾸지 않는다.
- 콘텐츠(Course~Resource)는 **파일이 원본**이고 DB는 색인 캐시다. `rc reindex` 또는 각 명령 실행 시 변경된 파일만 재색인한다.
- 학습 데이터(Progress~Report)는 **SQLite가 원본**이며 JSON으로 내보낼 수 있다.

## 9. 시스템 아키텍처 및 기술 스택 제안

아키텍처는 **코어 라이브러리를 중심으로 두 실행 모드**가 공유하는 구조다. Phase 1(현재)은 Python 단일 스택(uv + ruff + mypy + pytest)으로 코어 + CLI + 정적 사이트를 만든다. Phase 2에서 같은 코어 위에 API 서버·웹 프론트엔드·PostgreSQL을 얹는다.

```
curriculum/robotics-expert/   코스 콘텐츠 원본
  course.yaml                 코스 메타 + 모듈 순서
  <module>/module.yaml        모듈 메타 (level: 기초|중급|고급) + 레슨 순서
  <module>/<lesson>.md        레슨 (프런트매터 activities[]/resources[] + 본문 "이 단계 공부법" 절)
research_notes/           개인 노트 (Markdown)
reports/                  생성된 리포트 (Markdown)
src/robotics_curriculum/  코어 라이브러리 (Python): 콘텐츠 로더/검증기, 진도 저장(저장소 추상화: SQLite|PostgreSQL),
                          SM-2, 리포트 생성, 정적 사이트 빌더, CLI `rc`. 두 모드가 공유하는 유일한 비즈니스 로직 위치.
site/                     `rc build` 결과물 (정적 HTML, MkDocs 기반) — .gitignore 대상
tests/                    pytest (코어·CLI·API)
api/                      Phase 2: FastAPI 서버. 인증(로컬 계정 + OIDC), 역할 권한, REST(OpenAPI 스키마 공개), 헬스체크·메트릭
web/                      Phase 2: 웹 프론트엔드 (Next.js 또는 동급 — Phase 2 착수 시 결정). 로드맵·레슨·공부법·자료·대시보드·복습 UI
deploy/                   Phase 2: Docker Compose(api + web + postgres + reverse proxy), 환경 변수 예시, 백업 스크립트
docs/                     PRD, 콘텐츠 모델, 운영·기여·보안 문서
```

실행 모드별 구성:

| 구성 요소 | 로컬 모드 (Phase 1) | 서버 모드 (Phase 2) |
|---|---|---|
| 콘텐츠 | 저장소 파일 → 코어 로더 | 동일. 서버는 Git 체크아웃 또는 업로드된 번들을 색인 |
| 학습 데이터 저장소 | SQLite (`.rc/progress.db`) | PostgreSQL (Alembic 마이그레이션) |
| 사용자 | 고정 1명, 로그인 없음 | 로컬 계정 + OIDC, 역할 learner/author/admin |
| 화면 | 정적 사이트(읽기) + CLI(쓰기) | 웹 프론트엔드가 API를 호출 |
| 배포 | `uv tool install` 또는 `pipx` | Docker Compose; Kubernetes 매니페스트는 Phase 3 검토 |

주요 CLI 명령: `rc validate`, `rc build`, `rc status`, `rc next`, `rc show <lesson>`, `rc resources <lesson>|--module|--all`, `rc start|stop|log`, `rc done`, `rc quiz`, `rc review`, `rc note`, `rc report weekly|module`, `rc search`, `rc progress export|import`.

| 선택 | 이유 |
|---|---|
| 코어 라이브러리 분리 | 콘텐츠 검증·진도·복습·리포트 로직을 CLI와 API가 같은 코드로 쓴다. 두 모드의 동작 불일치를 막고 테스트를 한 곳에 모은다. |
| Python + FastAPI | 코어가 Python이라 API 서버를 같은 언어로 두면 경계가 없다. FastAPI는 OpenAPI 스키마, 타입 검증, 비동기 처리를 기본 제공한다. |
| 정적 사이트(MkDocs) | 로컬 모드에서 콘텐츠·공부법·로드맵·대시보드 읽기 전용 화면을 Markdown에서 바로 생성한다. 서버 모드에서도 콘텐츠 미리보기와 문서 사이트로 재사용한다. |
| SQLite / PostgreSQL | 로컬은 파일 하나로 백업·내보내기 가능한 SQLite, 서버는 동시성·백업·확장에 검증된 PostgreSQL. 저장소 추상화로 코어는 둘 다 지원. |
| Markdown + YAML 콘텐츠 | 앱 없이도 읽히고 Git diff로 리뷰 가능. 메타데이터(코스·모듈·레슨 프런트매터)만 YAML로 검증하고, 공부법은 본문 산문으로 둔다. 오픈소스 기여도 PR로 받는다. |
| Docker Compose | 자체 호스팅 관리자가 명령 한 번으로 올릴 수 있어야 한다. Kubernetes는 수요가 확인되면 Phase 3. |

제약: 로컬 모드의 정적 사이트는 읽기 전용이므로 진도 반영은 `rc build`를 다시 실행해야 보인다. 서버 모드가 이 마찰을 해소한다.

## 부록 A. 로보틱스 전문가 코스 전체 개요

코스 1개 `robotics-expert`, 모듈 10개(M1~M10), 레슨 49개. 자료 조사 보고서의 "로보틱스 전문가 코스 단계별 모듈 제안" 절(부록 B 출처)을 그대로 따른다. 레슨별 선수지식과 추천 자료 1~3개(총 145개, `resources[]` 형식)는 그 절에 있으며, 레슨 파일을 작성할 때 옮긴다.

- **총 소요**: 약 51주(주 8~10시간 기준; 기초 17주 + 중급 20주 + 고급 14주). 선택 레슨(L3.5, L9.4, L10.5)을 빼면 약 46주.
- **권장 학습 순서**: M1 → M2 → M3 → M4 → M8 → M5 → M6 → M7 → M9 → M10. M8(ROS 2·도구 개요)은 M5.5, M6.4, M7.4가 ROS 2 기초를 선수로 요구하므로 M4 뒤에 두며, M4와 병행할 수 있다. 번호는 단계 순서를 유지한다.
- **실습 성격 레슨**(L3.5, L5.5, L6.5, L7.5, L10.3~L10.5)은 학습자가 자기 환경에서 수행하는 과제이며, 플랫폼은 공부법과 자료만 안내하고 실행·판정하지 않는다(3.2절).

### C.1 P1-2 퀴즈·플래시카드·간격 반복 (FR-4.1~4.3)

**사용자 스토리**

- US-4.1 학습자로서, 레슨을 읽은 직후 퀴즈를 풀어 이해를 확인하고 각 문항의 해설을 보고 싶다.
- US-4.2 학습자로서, 틀린 문항과 레슨의 핵심 개념이 자동으로 복습 카드가 되기를 바란다.
- US-4.3 학습자로서, 오늘 복습할 카드만 보고, 내 응답에 따라 다음 복습일이 조정되기를 바란다.
- US-4.4 작성자로서, 퀴즈를 레슨 Markdown 안에 적고 `rc validate`로 오류를 바로 알고 싶다.

**퀴즈 블록 형식 (요구사항; 확정 스키마는 `docs/curriculum/CONTENT_MODEL.md`에 반영)**

- 레슨 본문의 펜스 코드 블록 ` ```quiz `(YAML). 레슨당 여러 블록 허용.
- 블록의 `activity`는 프런트매터 `activities[]` 중 `kind: quiz`인 활동 `id`를 가리킨다. 레슨에 quiz 활동이 하나뿐이면 생략 가능, 둘 이상인데 생략하면 검증 에러.
- `questions[]` 각 항목: `id`(레슨 내 유일), `type`(`single` | `multiple` | `truefalse` | `short`), `prompt`(Markdown, 수식 허용), `choices[]`(single/multiple 필수), `answer`(single: 선택지 인덱스 0부터; multiple: 인덱스 목록; truefalse: `true`/`false`; short: 허용 답 문자열 목록, 앞뒤 공백·대소문자 무시), `explanation`(필수), `concept`(선택; 지정하면 정오답과 무관하게 핵심 개념 카드를 만든다: `front`, `back`), `tags[]`(선택).

```quiz
activity: m1-vectors-matrices-quiz
questions:
  - id: q1
    type: single
    prompt: "두 벡터의 내적이 0이면 두 벡터는?"
    choices: ["평행하다", "직교한다", "같은 벡터다", "영벡터다"]
    answer: 1
    explanation: "내적이 0이면 사잇각이 90°이므로 직교한다."
    concept: { front: "내적이 0인 두 벡터의 관계", back: "직교(사잇각 90°)" }
  - id: q2
    type: short
    prompt: "3×3 회전행렬의 행렬식 값은?"
    answer: ["1", "+1"]
    explanation: "회전행렬은 직교행렬이고 반사를 포함하지 않으므로 det = +1."
```

**수용 기준**

| ID | 기준 | 검증 방법 |
|---|---|---|
| AC-4.1 | `rc validate`가 퀴즈 블록의 YAML 오류, 알 수 없는 `type`, `answer` 범위 밖, `explanation` 누락, `activity` 참조 오류, `id` 중복을 `파일경로: 메시지`로 보고하고 종료 코드 1을 반환한다. | 각 오류 유형별 픽스처 레슨 + pytest |
| AC-4.2 | `rc quiz <lesson>`이 문항을 순서대로 제시하고, 응답 즉시 정오와 해설을 보여주며, 끝나면 점수(정답 수/총 문항)와 소요 시간을 저장하고 해당 quiz 활동을 `done`으로 기록한다. 중간 종료 시 저장하지 않는다. | CLI 테스트(입력 스트림 모의), progress 조회 |
| AC-4.3 | 틀린 문항은 `source=quiz` 카드(front=prompt, back=정답+해설)가 되고, `concept`가 있는 문항은 `source=concept` 카드가 된다. 같은 문항을 다시 틀려도 카드가 중복 생성되지 않는다. 카드는 `lesson_id`와 문항 `id`를 보존한다. | 두 번 응시 후 카드 수 검증 |

| AC-4.5 | 알고리즘 선택(SM-2 채택, FSRS 보류 이유)이 `docs/adr/`에 기록되어 있다. | ADR 파일 존재·검토 |
| AC-4.6 | `rc status`에 오늘 복습 예정 수와 최근 7일 퀴즈 정답률이 표시된다. | CLI 출력 스냅샷 테스트 |
| AC-4.7 | 정적 사이트의 레슨 페이지에 퀴즈 문항이 정답·해설을 접은 상태(`<details>`)로 렌더링된다. 인터랙티브 채점은 Phase 2 웹 범위. | 빌드 결과 HTML 검사 |

범위 밖: 웹 인터랙티브 퀴즈, FSRS, 힌트, 퀴즈 결과의 사용자 간 비교.

### C.3 P2-2 인증·권한 (FR-10.3~10.7)

**사용자 스토리**

- US-AUTH.1 학습자로서, 이메일과 비밀번호로 가입·로그인하고 비밀번호를 잊으면 이메일로 재설정하고 싶다.
- US-AUTH.2 학습자로서, 기관 계정(OIDC)으로 한 번에 로그인하고 싶다.
- US-AUTH.3 학습자로서, 내 진행도·노트·리포트를 나만 보고, 언제든 전체를 내보내거나 계정을 삭제하고 싶다.
- US-AUTH.4 작성자로서, 콘텐츠 재색인과 미리보기는 할 수 있지만 다른 사용자의 데이터는 볼 수 없어야 한다.
- US-AUTH.5 관리자로서, 사용자를 초대·역할 변경·비활성화하고, 누가 무엇을 했는지 감사 로그로 확인하고 싶다.

**수용 기준**

| ID | 기준 | 검증 방법 |
|---|---|---|
| AC-AUTH.1 | 비밀번호는 Argon2id로만 저장된다. 평문·가역 저장·로그 노출이 없다. 정책: 최소 12자, 유출 비밀번호 목록 거부(선택), 재설정 토큰은 1회용·만료 30분. | 저장값 검사 테스트, 로그 grep 테스트 |
| AC-AUTH.2 | 로그인 실패 5회(계정·IP 기준, 15분 창) 후 지연 또는 임시 잠금. 성공·실패 모두 감사 로그. | 반복 요청 테스트 |
| AC-AUTH.3 | OIDC Authorization Code + PKCE 흐름이 모의 IdP 픽스처로 끝까지 통과하고, 같은 이메일의 로컬 계정과 연결된다. 제공자 설정은 환경 변수. | 통합 테스트 |
| AC-AUTH.4 | 역할 매트릭스(learner/author/admin × 모든 엔드포인트)가 표로 문서화되고, 테스트가 허용·401·403을 모두 확인한다. 기본 역할은 learner. | 매트릭스 파라미터화 테스트 |
| AC-AUTH.5 | 사용자 A의 진행도·카드·노트·리포트가 사용자 B의 조회·수정 요청에 노출되지 않는다. 모든 학습 데이터 쿼리에 `user_id` 조건이 있다. | 교차 접근 테스트, 코드 리뷰 |
| AC-AUTH.6 | 사용자는 자기 데이터 전체를 JSON으로 내보내고(로컬 모드 `rc progress import`와 호환), 계정 삭제 시 학습 데이터는 즉시 삭제, 감사 로그의 개인 식별자는 보존 기간(설정, 기본 90일) 뒤 익명화된다. | 삭제 후 조회 테스트 |
| AC-AUTH.7 | 세션/토큰 방식, 만료·갱신·로그아웃 무효화 정책이 ADR에 기록되고 구현과 일치한다. 기기별 세션 목록·개별 종료는 P1. | ADR + 테스트 |
| AC-AUTH.8 | OWASP ASVS L2의 V2(인증), V3(세션), V4(접근 제어) 항목 체크리스트를 작성해 통과·미해당을 표시한다. CSRF 방어와 보안 헤더(CSP, HSTS)가 적용된다. | 체크리스트 파일, 헤더 테스트 |

범위 밖: 결제·구독, 그룹/코호트(P2), 다중 조직(테넌트) 분리.
