## 1. 개요

로보틱스를 체계적으로 학습하려는 사람을 위해 **커리큘럼(무엇을, 어떤 순서로 배울지)** 과 **학습 보조 도구(진도 추적, 복습, 실습, 리포트)** 를 하나로 묶은 플랫폼이다.

콘텐츠는 저장소 안의 Markdown/YAML 파일로 관리하여 Git으로 버전 관리하고, 웹 앱은 그 콘텐츠를 읽어 학습 경험(로드맵, 진도, 퀴즈, 실습 검증)을 제공한다.

## 2. 배경 및 문제 정의

로보틱스는 수학(선형대수, 미적분), 물리(동역학), 제어, 소프트웨어(ROS 2, 시뮬레이션), 하드웨어(센서, 액추에이터)가 얽혀 있어 독학 시 다음 문제가 반복된다.

1. **순서 혼란**: 무엇을 먼저 배워야 하는지(선수지식) 명확하지 않다.
2. **분산된 자료**: 책, 논문, 강의, 블로그가 흩어져 있고 메모(`research_notes/`)와 학습 내용이 연결되지 않는다.
3. **이론과 실습의 단절**: 개념을 읽어도 시뮬레이터(Webots)에서 직접 돌려보는 단계로 이어지지 않는다.
4. **망각**: 복습 체계가 없어 몇 주 뒤 다시 처음부터 본다.
5. **진도 불투명**: 어디까지 했고 얼마나 남았는지, 주간 단위로 무엇을 했는지 알 수 없다.

## 3. 목표와 비목표

### 3.1 목표

- G1. 선수지식 그래프가 있는 **구조화된 커리큘럼**을 제공한다.
- G2. 레슨 단위로 **진도·시간·이해도**를 기록하고 대시보드로 보여준다.
- G3. 퀴즈와 **간격 반복(spaced repetition)** 으로 복습을 자동화한다.
- G4. 레슨마다 **Webots 실습**을 붙이고, 결과를 자동으로 검증한다.
- G5. 학습 기록으로 **주간/모듈 리포트**를 자동 생성해 `reports/`에 남긴다.

### 3.2 비목표 (이번 범위 밖)

- 다수 사용자를 위한 상용 LMS(결제, 조직 관리, SSO)
- 실제 로봇 하드웨어 원격 제어
- 콘텐츠 마켓플레이스 또는 외부 강의 판매
- 모바일 네이티브 앱 (반응형 웹까지만)

## 4. 대상 사용자

| 페르소나 | 설명 | 핵심 니즈 |
|---|---|---|
| **P1. 독학 학습자 (주 사용자)** | 로보틱스 입문~중급. 저장소 소유자 본인이 첫 사용자. | 순서대로 배우기, 진도·복습 관리, 실습 연결 |
| **P2. 콘텐츠 작성자** | 커리큘럼을 추가·수정하는 사람(초기에는 P1과 동일 인물) | Markdown으로 쉽게 작성, 검증 도구, 미리보기 |
| **P3. 소규모 스터디 그룹 (후순위)** | 2~10명이 같은 트랙을 함께 진행 | 각자 진도 분리, 간단한 공유 |

MVP는 P1/P2가 동일 인물인 **단일 사용자** 환경을 전제로 한다. 멀티유저는 데이터 모델에 `user_id`를 미리 두는 수준으로만 대비한다.

## 5. 핵심 사용자 시나리오

1. **첫 방문**: 로드맵 화면에서 트랙(예: "로보틱스 기초")을 고르면, 선수지식 그래프와 예상 소요 시간을 보고 시작 레슨이 추천된다.
2. **레슨 학습**: 레슨 본문(Markdown) → 핵심 개념 체크 퀴즈 → 실습 과제 순으로 진행하고, 완료 시 이해도(1~5)와 메모를 남긴다.
3. **실습**: 레슨에 연결된 Webots 월드와 컨트롤러 템플릿을 받아 구현한 뒤, 플랫폼이 시뮬레이션을 실행하고 판정 기준(예: 목표 지점 도달, 오차 범위)으로 통과 여부를 알려준다.
4. **복습**: 매일 대시보드에 오늘 복습할 카드 N개가 뜨고, 정답 여부에 따라 다음 복습 일정이 조정된다.
5. **주간 리포트**: 매주 학습 시간, 완료 레슨, 퀴즈 정답률, 막힌 지점을 Markdown 리포트로 생성해 `reports/YYYY-WW.md`에 저장한다.
6. **콘텐츠 작성**: 작성자가 `curriculum/` 아래에 레슨 파일을 추가하면, 검증 명령이 frontmatter·선수지식 참조·순환 의존을 검사하고 앱에 즉시 반영된다.

## 6. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = v1.0, **P2** = 이후.

### FR-1. 커리큘럼 콘텐츠 모델 및 관리 (P0)

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-1.1 | 콘텐츠 계층은 `Track > Module > Lesson > Activity`로 구성한다. | 4단계 계층을 파일 시스템 디렉터리와 1:1로 대응시킨다. |
| FR-1.2 | 레슨은 YAML frontmatter가 있는 Markdown 파일이다. | 필수 필드: `id`, `title`, `prerequisites[]`, `estimated_minutes`, `objectives[]`, `tags[]`. |
| FR-1.3 | Activity 타입은 `reading`, `quiz`, `lab`, `project`, `external`(외부 강의/논문)을 지원한다. | 각 타입별 스키마 정의 및 렌더링. |
| FR-1.4 | 콘텐츠 검증 CLI를 제공한다. | 누락 필드, 존재하지 않는 선수지식 ID, 순환 의존을 감지하면 비정상 종료 코드를 반환한다. |

## 8. 개념 데이터 모델

```
Track ──< Module ──< Lesson ──< Activity (reading | quiz | lab | project | external)
                      │  prerequisites: Lesson[]  (DAG)
                      └──< Resource (n:m)

Progress   (user_id, activity_id, status, understanding 1-5, note, updated_at)
Session    (user_id, lesson_id, started_at, ended_at, minutes)
Card       (id, lesson_id, front, back, source: quiz|concept)
Review     (card_id, reviewed_at, rating, next_due, interval, ease)
LabRun     (activity_id, submitted_at, passed, metrics_json, log_path, code_snapshot_path)
Note       (lesson_id, path, updated_at)   ← research_notes/ 파일을 색인
Report     (kind: weekly|module, period, path)
```

- 콘텐츠(Track~Resource)는 **파일이 원본**이고 DB는 색인 캐시다. 앱 시작 또는 파일 변경 시 재색인한다.
- 학습 데이터(Progress~Report)는 **SQLite가 원본**이며 JSON으로 내보낼 수 있다.

## 9. 시스템 아키텍처 및 기술 스택 제안

```
curriculum/            Markdown + YAML (콘텐츠 원본)
research_notes/        개인 노트 (Markdown)
reports/               생성된 리포트 (Markdown)
labs/                  Webots 월드·컨트롤러 템플릿·판정 스크립트
backend/   (Python)    FastAPI + SQLite(SQLModel) + 콘텐츠 로더/검증기 + 간격 반복 + 리포트 생성 + Webots 러너
frontend/  (Next.js)   로드맵 그래프, 레슨 뷰어(MDX/KaTeX), 대시보드, 복습 UI
cli/       (Python)    `rc validate`, `rc report weekly`, `rc lab run <id>`, `rc reindex`
```

| 선택 | 이유 |
|---|---|
| Python 백엔드 | Webots 컨트롤러와 판정 스크립트가 Python이라 동일 런타임에서 실행·검증이 쉽다. `.gitignore`도 이미 Python 전제. |
| Next.js 프론트 | MDX 렌더링, 수식, 그래프 시각화 생태계가 풍부하다. |
| SQLite | 단일 사용자·로컬 우선. 파일 하나로 백업·내보내기 가능. |
| Markdown 콘텐츠 | 앱 없이도 읽히고 Git diff로 리뷰 가능. |

대안: 프론트 없이 **CLI + 정적 사이트(MkDocs)** 로 시작하는 축소안도 가능하다. 다만 진도·복습 UI는 정적 사이트로 구현이 어렵기 때문에, Phase 0에서 CLI로 검증한 뒤 Phase 1에서 웹을 붙이는 것을 권장한다.

## 12. 리스크 및 가정

| 리스크 | 영향 | 대응 |
|---|---|---|
| 콘텐츠 작성이 가장 큰 병목 | 플랫폼이 비어 있으면 가치 없음 | Phase 0을 콘텐츠에 집중, AI 보조 초안 생성(FR-8.2) 조기 도입 |
| Webots headless 자동화 불안정 | FR-5.3 지연 | MVP는 수동 실행 가이드로 한정, 자동 검증은 Phase 2 |
| 과도한 기능 범위 | MVP 지연 | P0 외 기능은 이슈로만 남기고 구현하지 않음 |
| 단일 사용자 가정 고착 | 멀티유저 전환 비용 | 모든 학습 데이터에 `user_id` 컬럼 선반영 |

**가정**: 첫 사용자는 저장소 소유자 본인이며 Linux + Webots 환경이 이미 갖춰져 있다. 스택은 `.gitignore`의 Python/Node 항목을 근거로 정했고, 확정은 아니다.
